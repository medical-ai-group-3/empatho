# 병원 웹 — 화면과 권한

병리과 · 영상의학과. 두 과의 화면 다섯 장씩, 열 장.

이 문서는 **어느 화면이 무엇을 하는 자리인지** 헷갈리지 않으려고 쓴 것이다.
코드를 열기 전에 여기를 먼저 본다.

---

## 왜 두 과를 같이 만들었나

명세를 나란히 놓고 보면 구조가 거의 같다. 병리과 명세에도 그렇게 적혀 있다.

> 영상의학과와 구조가 거의 같다. 판독 대상이 검사(study)가 아니라 검체(specimen)라는 점,
> AI 소견 내용이 다르다는 점이 갈린다.

그래서 **화면 뼈대는 한 벌만 만들고**(`screens/`), 과마다 다른 것은
설정 파일에 모았다(`dept/`). 한쪽을 고치면 다른 쪽도 같이 고쳐진다.

```
screens/Queue.jsx    ← 1장. 두 과가 같이 쓴다
screens/Upload.jsx   ← 2장
screens/Read.jsx     ← 3장
screens/List.jsx     ← 4장
screens/Amend.jsx    ← 5장

dept/pathology.jsx   ← 병리과가 다른 것만
dept/radiology.jsx   ← 영상의학과가 다른 것만
```

## 화면 열 장

| # | 화면 | 병리과 | 영상의학과 |
|---|---|---|---|
| 1 | 대기 큐 | `/hospital/pathology` | `/hospital/radiology` |
| 2 | 업로드 | `…/specimens/:id/upload` | `…/studies/:id/upload` |
| 3 | 판독 | `…/read/:id` | `…/read/:id` |
| 4 | 전체 목록 | `…/specimens` | `…/patients` |
| 5 | 판독 정정 | `…/read/:id/amend` | `…/read/:id/amend` |

### 1장 · 대기 큐

**아직 아무도 맡지 않은 일**이 도착 순서대로 쌓인다. 과 전체가 같은 목록을
본다. 내가 집으면 다른 선생님 화면에서 사라진다.

- 병리과 — 간호·유방외과가 바인딩을 끝낸 **검체**
- 영상의학과 — 유방외과가 낸 **촬영 오더**

여기서 **하지 않는 일**
- 순서 바꾸기 — 순번은 표시 전용이다. 여럿이 보는 큐라 내가 끌어 옮기면
  나만 다른 화면을 보게 된다. 대신 검색으로 건너뛴다
- 반려 — 검체나 오더가 이상한지 시스템이 판단할 수 없다

동시에 두 사람이 집으면 먼저 닿은 하나만 성공한다. 나머지는 409 를 받고
「다른 선생님이 이미 맡았습니다」가 뜬다.

### 2장 · 업로드

파일을 올리고 **그 자리에서 AI 분석을 건다.**

**AI 분석은 여기서 시작하고 여기서 끝난다.** 분석이 끝나야 3장으로 넘어갈
수 있다. 그래서 판독 화면에는 「분석 중」이라는 상태가 아예 없다.

MRI 는 175초다. 화면 앞에서 기다릴 필요가 없어서, 큐로 나갔다 다시 들어와도
진행 상태가 그대로 보인다. 클라이언트에 타임아웃을 두지 않는다.

파일 바이트는 Django 를 안 거친다. 티켓을 받아 Go 관문으로 곧장 올라간다.

### 3장 · 판독

원본 위에 AI 결과를 얹어 보고 소견을 써서 확정한다.
**[저장]을 누르면 유방외과로 나간다. 되돌릴 수 없다.**

- 탭이 없다. 원본 한 장에 마스크를 얹고 투명도로 조절한다
- [AI 활성화] 버튼이 없다. 1차 판독 게이트는 팀 결정으로 없앴다
- 패널 셋이 각각 접힌다. **셋 다 접으면 뷰어만 남는다**
- AI 값과 사람 값을 섞지 않는다. 다른 컬럼이고 화면에서도 다른 자리다

### 4장 · 전체 목록

지난 것까지 전부 찾아보는 자리. 1장이 「아직 아무도 안 맡은 것」만 보여주는
데 비해 여기는 **끝난 것도 남아 있다.** 판독 정정도 여기서 들어간다.

**보이는 범위가 사람마다 다르다.** 리포트 권한이 `own` 이면 내가 맡은 환자만
보인다. 화면 위에 그 사실을 적어 둔다 — 목록이 짧은 이유를 모르면 누락으로
오해한다.

「확인」이 아니라 **「열람」**이다. 유방외과가 리포트를 열면 시각이 자동으로
찍히는 것이지, 사람이 확인했다고 누른 것이 아니다.

### 5장 · 판독 정정

이미 확정해서 나간 판독을 고친다. **옛 값은 지워지지 않는다.**

- 병리과 — `specimen.amend_history` (JSONB) 에 옛 값을 밀어넣는다.
  검체는 물건이라 행을 늘릴 수 없다
- 영상의학과 — 새 `assessment` 행을 만들고 옛 행의 `superseded_by` 가
  그것을 가리킨다

정정 사유 · 세부 분류 · 세부 소견 셋 다 필수다.

## 두 과가 갈리는 지점

| | 병리과 | 영상의학과 |
|---|---|---|
| 판독 단위 | 검체 `specimen` | 검사 `study` (큐는 오더 `exam_order`) |
| 등급 체계 | **`b_category` b1~b5** | **BI-RADS** |
| AI 소견 | sTIL · TSR · 세포 수 · 간질 상태 | 모달리티마다 다름 (초음파 · 맘모 · MRI) |
| 정정 이력 | `amend_history` JSONB | 새 행 + `superseded_by` |
| 임시저장 표시 | 목록에 안 띄운다 | 「작성 중」으로 띄운다 |
| 여기만 있는 것 | — | 조영제 알레르기 경고 · 재촬영 요청 · 병변 직접 추가 · 오탐 표시 · 모달리티 구분 |
| 단계 하나 더 | — | 업로드 확정(`…/complete`) 이 분석 시작과 따로 있다 |

**등급을 헷갈리지 말 것.** 화면 라벨에 「BI-RADS」라고 적혀 있어도 병리는
B 분류를 쓴다. BI-RADS 는 영상 체계다.

## 병리 AI 소견에서 지켜야 할 것

1. **`stil_nucleus` 를 화면에 내지 않는다.** 보정 전 값이라 임상 기준의
   1/12 로 나온다. 화면에도 소견문에도 안 낸다. 내는 것은
   `stil_calibrated` 뿐이다
2. **간질이 없으면 0% 가 아니라 「평가 불가」다.** `stroma_status=absent`
   면 sTIL 이 null 이다. 0% 로 그리면 정반대 뜻이 된다
3. **크롭 여러 장을 평균 내지 않는다.** 자른 자리에 따라 0~36% 로 흔들린다.
   평균은 우리가 만든 값이지 모델이 낸 값이 아니다

## 영상 AI 소견에서 지켜야 할 것

1. **미검출은 정상이 아니다.** 「정상」이 아니라 「판정 못 함」 + 사유
2. **서술어를 만들지 않는다.** 「경계가 불규칙합니다」 같은 문장을 화면이
   지어내지 않는다. 값과 확신도만 낸다
3. **초음파 크기는 px 뿐이다.** pixel spacing 이 없어 mm 로 못 바꾼다
4. **악성 확률을 화면에 내지 않는다**

## 권한

### 어떻게 도는가

```
로그인 → GET /me → { name, role, dept, perms: ["pathology.queue.view", …] }
화면은 그 perms 배열만 보고 켜고 끈다
```

**화면이 직책으로 직접 판단하지 않는다.** 「교수면 저장 가능」 같은 코드를
넣으면 관리자가 권한을 바꿔도 화면이 안 따라간다. 화면은 항상 `perms` 만
본다. 직책은 이름 옆에 적는 표시용이다.

### 감추기와 끄기

| | 어떻게 | 어디에 |
|---|---|---|
| **감춘다** | 메뉴에서 빠진다 | 화면 전체. 눌러야 「권한 없음」만 나올 자리를 띄워 두면 헛걸음한다 |
| **끈다** | 비활성 + 「권한이 없습니다」 | 버튼. 사라지면 고장으로 오해한다 |

### 권한 목록

과마다 같은 12개 + 영상 전용 3개 + 리포트 범위 3개.
`{과}` 자리에 `pathology` 또는 `radiology` 가 들어간다.

| 키 | 무엇을 여는가 |
|---|---|
| `{과}.queue.view` | 1장 화면 |
| `{과}.queue.assign` | 1장 [다음 환자] |
| `{과}.upload.view` | 2장 화면 |
| `{과}.upload.send` | 2장 [파일 선택] |
| `{과}.ai.run` | 2장 [AI 분석 시작] |
| `{과}.ai.view` | 3장 AI 소견 패널 (없으면 패널 자체가 없다) |
| `{과}.read.view` | 3장 화면 |
| `{과}.read.draft` | 3장 [임시저장] |
| `{과}.read.finalize` | 3장 [저장] — **되돌릴 수 없다** |
| `{과}.list.view` | 4장 화면 |
| `{과}.amend.view` | 5장 화면 |
| `{과}.amend.save` | 5장 [저장] |

전체 목록은 `perm.js` 의 `CATALOG` 에 있다. **그 배열이 그대로 관리자
화면의 체크박스 목록이다.**

### 직책별 기본값 — 목업 전용

`perm.js` 의 `mockPerms()` 에 있다. **실제로는 서버가 내려준다.**
직책 이름도 우리가 임시로 붙인 것이라, `account.role` 의 영문 코드로
바꾸는 것은 관리자 화면 담당의 몫이다.

| 직책 | 집기 | 업로드 | 분석 | 임시저장 | 확정 | 정정 | 리포트 |
|---|---|---|---|---|---|---|---|
| 과장·교수 | ○ | ○ | ○ | ○ | ○ | ○ | 전체 |
| 전문의 | ○ | ○ | ○ | ○ | ○ | ○ | 우리 과 |
| 전공의 | ○ | ○ | ○ | ○ | ✕ | ✕ | 내 담당 |
| 기사 | ○ | ○ | ○ | ✕ | ✕ | ✕ | — |
| 열람 | ✕ | ✕ | ✕ | ✕ | ✕ | ✕ | 내 담당 |

정한 기준
- **전공의는 확정과 정정을 못 한다.** 되돌릴 수 없고 유방외과로 나가는
  동작이라 그렇다. 임시저장까지는 한다
- **기사는 판독을 못 한다.** 올리고 분석 거는 데까지다

## 아직 안 채운 자리

껍데기는 다 섰지만 규격이 없어 비워 둔 곳이다. **붙일 자리는 만들어 두었다.**

| 무엇 | 어디 | 무엇이 정해져야 하나 |
|---|---|---|
| 원본 영상 주소 | 3장 | `read` 응답에 storage_object(키)와 픽셀 크기(w·h). 추가 예정 |
| 병리 마스크 주소 | 3장 | `read` 응답에 image 행(kind=mask). 추가 예정 |
| 파일 전송 | 2장 | 티켓 발급 → Go **업로드** 규격 (다운로드는 확정) |
| 쪽 넘김 | 4장 | `page` / `cursor` 규격 |
| 템플릿 불러오기 | 5장 | 무엇을 불러오는지 |
| 맘모 박스 좌표 형식 | `lib/Stage.jsx` | `[x1,y1,x2,y2]` 로 가정 중. 우리 서빙 출력 확인 필요 |
| 맘모 원본 픽셀 크기 | 목업 | 우리 서빙이 내는 값. 지금은 1000×1250 으로 두었다 |

**고른 파일을 올라간 것처럼 그리지 않는다.** 「전송 준비 중」으로 구분해
표시한다. 실패했을 때 올라간 줄 알고 넘어가는 것을 막기 위해서다.

## 뷰어에 무엇을 얹나

| 과 | 모달리티 | 형식 | 어떻게 그리나 |
|---|---|---|---|
| 병리 | — | **PNG 마스크** | `<img>` 를 원본 위에 겹치고 투명도 |
| 영상 | 초음파 | **폴리곤 좌표** | SVG `<polygon>` |
| 영상 | 맘모 | **박스 좌표** | SVG `<rect>` — 검출 모델이라 마스크가 없다 |
| 영상 | MRI | 3D 메시 | 2D 뷰어에 안 얹는다 (Garage 에서 따로) |

**좌표는 원본 픽셀 기준**이다. SVG 에 `viewBox` 를 원본 크기로 걸어 두어,
확대하든 줄이든 브라우저가 알아서 같이 움직인다. 우리가 좌표를 다시
계산하지 않는다. 그래서 **원본의 픽셀 크기(w·h)가 반드시 필요하다.**

원본 크기 (2026-09-16 확인)

| | 크기 |
|---|---|
| 병리 크롭 | 512 × 512 |
| 초음파 | 274 × 351 (추론은 1008² 로 늘려 쓰지만 응답은 원본으로 돌아온다) |
| 맘모 | 미확정 — 우리 서빙이 내는 값 |
| MRI | 512 × 512 × 176장. 2D 뷰어 밖 |

**초음파 폴리곤은 구멍이 있다.** `outer` · `holes` · `n_components` 로
온다. `<polygon>` 은 구멍을 모르므로, 바깥과 구멍을 한 `<path>` 의 여러
조각으로 넣고 `fill-rule="evenodd"` 를 건다. 겹친 안쪽이 자동으로 뚫린다.

⚠ **형태 지표를 폴리곤에서 다시 계산하지 않는다.** 표시용으로
단순화돼 있어 서버 값과 달라진다. 면적·직경은 서버가 준 값을 쓴다.

좌표를 도형으로 바꾸는 자리는 `lib/Stage.jsx` 아래쪽 두 함수뿐이다.
형식이 바뀌면 거기만 고친다.

```
boxesFromLesions()   맘모 박스      ⚠ [x1,y1,x2,y2] 로 가정 — 확인 필요
polygonsFromAi()     초음파 폴리곤   outer / holes / n_components
```

### 영상을 어떻게 받아오나

```
POST /api/v1/tickets { purpose:"download", scope_id }
  → { token, expires_at, object_key_prefix, max_bytes }
GET /svc/v1/files/<key>   Authorization: Bearer <티켓 토큰>
```

읽기 티켓은 1회용이 아니라 한 세션에 하나면 된다. `lib/files.js` 가
대상(검체·검사)마다 하나를 받아 여러 장에 같이 쓰고, 만료 30초 전에
새로 받는다.

⚠ **`<img src="…">` 는 Authorization 헤더를 못 보낸다.** 그래서 주소를
그냥 꽂으면 401 이 난다. `lib/files.js` 가 `fetch` 로 받아 blob 주소로
바꾼 다음 그것을 `<img>` 에 준다. 화면이 사라질 때 revoke 한다.

## 갈아탈 때 고칠 곳

`api.js` 에 `⚠` 로 표시한 셋뿐이다.

1. `BASE` — 주소 앞머리. `.env.local` 의 `VITE_API_BASE` 로 덮을 수 있다
2. `unwrap()` — 봉투를 벗기는 방식. **확정됨**
   성공 `{success, data, error:null, trace_id}` · 실패 `{success:false, data:null, error:{code,message,details}, trace_id}`
   서버의 `message`·`details` 를 화면의 `detail`·`fields` 로 여기서 바꿔 준다
3. `setToken()` — 로그인 토큰. **메모리에만 둔다. localStorage 금지**

목업일 때만 `/api/v1/hospital` 을 쓴다. 이건 목업 서버를 환자 앱 목업과
갈라놓기 위한 것이지 실제 서버 규격이 아니다. **실제 서버는 `/api/v1` 하나다.**
