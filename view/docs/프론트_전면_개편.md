# EMPATHO 병원 화면 — 다시 만들기

2026-09-21 · 이 문서 하나로 `hospital/`(의료진 화면)을 처음부터 다시 만든다.
목표는 **실제 병원에서 하루 종일 쓸 수 있는 화면**이다. 시연용 목업이 아니다.

---

## 0. 무엇을 만드는가

유방암 진단 흐름을 네 과가 한 화면 체계에서 이어 가는 업무 시스템이다
(접수·간호 · 영상의학과 · 병리과 · 유방외과).

```
환자 ─ 원무(접수) ─ 간호(문진·배정) ─ 유방외과(오더) ─ 영상의학(촬영·판독)
                                          │
                                          ├─ 병리(검체·판독)
                                          │
                                    유방외과(종합·결정) ─ 종결
```

쓰는 사람은 교수 · 전공의 · 기사 · 간호사 · 행정이고, **보는 화면이 다르다.**
같은 사람이 하루에 같은 화면을 수십 번 연다. 그래서 이 화면은 예뻐야 하는
것이 아니라 **빨라야 하고, 틀리지 않아야 하고, 지치지 않아야 한다.**

---

## 1. 절대 규칙

### 1.1 환자 안전

* **환자를 다루는 모든 화면 맨 위에 환자 띠가 있다.** 이름 · 나이 · 성별 ·
  환자번호 · 경고. 지금 누구를 보고 있는지 한 번도 헷갈리면 안 된다.
* **경고는 맨 앞에 온다** — 조영제 알레르기, 복용 중인 항응고제. 스크롤
  아래에 숨기지 않는다.
* **되돌릴 수 없는 동작은 한 번 더 묻는다** — 판독 확정, 진료 종결, 검체
  폐기. 물을 때는 무엇이 일어나는지 적는다. 「확실합니까?」만 띄우지 않는다.
* **AI 는 판정하지 않는다.** 화면 어디에도 AI 의 악성도 점수를 찍지 않는다.
  AI 는 「여기를 보라」고 표시할 뿐이고, 등급은 사람이 매긴다. 이 문장을
  AI 패널에 적어 둔다.

### 1.2 기록

* **지우지 않고 쌓는다.** 판독을 고치면 새 행이 생기고 옛 행이 남는다.
  결정을 바꾸면 새 결정을 남긴다. 화면에도 그렇게 보여 준다 — 「고침」이
  아니라 「정정본이 생겼고 원본은 여기 있다」.
* **누가 언제 했는지 항상 보인다.** 판독·결정·처분 줄에는 사람 이름과
  시각이 붙는다.
* **확정된 것만 환자에게 나간다.** 초안은 환자 앱에 보이지 않는다.

### 1.3 자료의 정직함

* **없는 값을 지어내지 않는다.** 평균 대기 시간, 처리율, 만족도 — 서버에
  없으면 화면에 없다. 빈 칸을 「0」이나 「—」로 채워 있는 것처럼 보이게
  하지 않는다.
* **모르면 모른다고 쓴다.** 「불러오지 못했습니다」가 빈 목록보다 낫다.
* **그래프를 쓰지 않는다.** 판독 영상 옆에서 색이 병변 표시와 싸운다.
  수치는 글자와 표로 적는다. 상태는 **모양**으로 가른다.

### 1.4 권한

* **권한이 없는 화면·메뉴는 안 보인다.** 눌러 봐야 「권한 없음」만 나올
  자리를 띄우면 매번 헛걸음한다.
* **권한이 없는 버튼은 감추지 말고 끈다.** 사라지면 고장으로 오해한다.
  끄고, 왜 못 누르는지 붙여 준다.
* 확정 권한은 교수에게만 있다. 전공의는 쓸 수 있고 확정은 못 한다.

## 2. 무엇을 다시 쓰고 무엇을 지키는가

**다시 쓴다 — 화면(view) 층**

```
hospital/screens/**      모든 화면
hospital/dept/**/screens/**
hospital/lib/ 의 화면 부품 (Top · Page · Parts · Body · Stage …)
hospital/hospital.css
```

**지킨다 — 배관(plumbing) 층. 손대지 말 것**

| 파일 | 왜 |
|---|---|
| `api.js` | 서버와의 계약. **주석 하나하나가 실제로 당한 사고의 기록이다** — 봉투 언랩, 페이지네이션, 날짜 경계, 큐 필터. 지우면 같은 함정을 다시 밟는다 |
| `perm.js` | 권한 판정 |
| `codes.js` | BI-RADS · B분류 · 모달리티 같은 코드표 |
| `tokens.css` | 디자인 수치 전부. 여기 없는 숫자를 CSS 에 쓰지 않는다 |
| `nav.js` | 화면 등록표. 화면을 더하면 여기 줄을 더한다 |
| `lib/useApi.js` `lib/session.js` `lib/useMe.js` `lib/files.js` | 불러오기 · 로그인 · 파일 |
| `lib/dicom/**` | 뷰어. 건드릴 이유가 없다 |

화면을 새로 쓰되 **부르는 함수는 그대로 쓴다.** `api.js` 에 없는 경로가
필요하면 만들지 말고 8장에 적는다.

## 3. 화면 지도

```
/hospital                      → 내 과의 홈으로 보냄
/hospital/me                   내 정보 (과 바깥)
/hospital/patients/:id         환자 상세 (과 바깥 · 모든 과 공통)

/hospital/nursing              홈          ← 원무과 + 간호과 = 「접수·간호」
            /intake            접수 · 오늘 현황
            /waiting           내원 대기 · 유방외과 배정
            /patients          환자 목록
            /reservations      예약 판 (달력) · 예약 신청 탭
            /followups         추적 관리

/hospital/radiology            홈
              /queue           촬영 대기 큐
              /patients        전체 목록
              /studies/:id/upload
              /read/:id
              /read/:id/amend  판독 정정

/hospital/pathology            홈
              /queue           검체 접수 대기
              /specimens       전체 목록
              /specimens/:id/upload
              /read/:id

/hospital/breast               홈
            /waiting           내 환자
            /patients          전체 환자
            /patients/:id/review     검사 종합
            /patients/:id/decision   수술 결정
            /discordances/:id        불일치 처분

/hospital/admin                관리자 (Django admin 으로 넘김)
```

주소는 `nav.js` 의 표에서 나온다. 화면에서 주소 문자열을 직접 쓰지 않고
항상 `go.*` 를 쓴다.

## 4. 공통 틀

### 4.1 내비게이터 — 크고 분명하게

참고한 화면(오름차트 「오늘의 현황」)처럼 **위쪽을 아끼지 않는다.** 하루에
수백 번 누르는 자리라 작게 만들면 손해다.

```
┌────────────────────────────────────────────────────────────────────────┐
│ ◈ EMPATHO │ 미래 대학병원 │ [박]박지훈님 · 유방외과                    │  60px 짙은 띠
│              ⌕ 환자 이름 · 환자번호 · 생년월일      09-21(월) 14:32 ◍ │
├────────────────────────────────────────────────────────────────────────┤
│  오늘의 현황 │ 접수·간호 9 │ 영상의학 7 │ 병리 5 │ 유방외과 6 │ 내 일     │  56px 과 줄
├────────────────────────────────────────────────────────────────────────┤
│  대기 환자 │ 전체 환자 │ 검사 종합      24 접수 · 11 진행 · 7 판독 대기  │  44px 화면 줄
└────────────────────────────────────────────────────────────────────────┘
```

* **탭이 크다.** 글자 **16.5px**, 높이 **56px**, 좌우 여백 **26px**.
  지금 탭은 **굵게(700) + 아래 4px 강조선**으로. 회색 작은 글씨로 만들지 말 것.
  띠 60 + 과 줄 56 + 화면 줄 44 = **160px**. 위쪽을 아끼지 않는다고 한 것이 이 뜻이다.
  ⚠ 판독·간호·유방외과 화면 높이는 `--top-total` 에서 나오므로 여기만
  고치면 아래가 따라온다. 숫자를 다시 박지 말 것.
* **탭마다 건수 뱃지.** 그 과에서 지금 내 손이 필요한 건수다. 0이면 안 붙인다.
  ⚠ 건수를 상단바에서 세려면 과마다 목록을 불러야 한다. 8장 1번(`GET /home`)이
  붙기 전에는 **지금 보고 있는 과의 숫자만** 넣고 나머지는 비운다.
* **검색바가 가운데에 크고 길다**(최소 420px). 이 시스템에서 제일 많이 하는
  행동이 환자 찾기다. `/` 로 바로 들어간다.
  ⚠ **찾는 열쇠는 과마다 다르다.** 생년월일로 찾는 것은 **원무뿐**이다 —
  창구 본인확인이라 필요하다. 병리 · 영상 · 유방외과는 **이름 · 환자번호**
  까지다. 문구를 전 과에 같은 것으로 깔지 말고, 화면 등록 표에서 그 과의
  열쇠를 읽어 쓴다.
* **내비게이터는 두 층이다.** 과를 고르는 줄과, 그 과의 화면을 고르는 줄.
  **둘이 다른 모양이면 안 된다** — 화면 줄이 작고 밋밋하면 「내비게이터가
  둘」로 보인다. 같은 언어를 쓰고 **크기만** 다르다.

  | | 과 줄 | 화면 줄 |
  |---|---|---|
  | 바탕 | **검은 띠** (1층과 이어진다) | 흰 줄 |
  | 높이 · 글자 | 56px · 16.5px 700 | 44px · 14.5px 600 |
  | 고른 것 | 흰 글자 + 바탕 한 톤 밝게 + 아래 4px | 검은 글자 + 아래 3px |
  | 강조선 | 하나를 옮긴다 | **같은 방식으로 옮긴다** |
  | 얹으면 | 바탕이 옅게 (120ms) | 같다 |

  ⚠ **과 줄을 흰색으로 만들지 말 것.** 1층과 2층이 이어진 검은 덩어리이고
  3층만 흰 줄이다. 2·3층이 둘 다 희면 층이 안 갈려서, 내비게이터가 통째로
  눈에 안 들어온다.

  화면 줄은 **왼쪽**에 둔다. 내비게이터는 왼쪽에서 시작한다.
  ⚠ 화면 줄을 요약 줄 오른쪽에 얹지 말 것. 그러면 길이 숫자에 묻힌다.
* **요약 줄은 따로 두지 않는다.** 숫자는 **화면 줄 오른쪽 끝**에 붙인다.
  줄을 하나 더 만들면 내비게이터가 너무 두꺼워진다 (60+56+44 = 160px).
  숫자 네다섯 개를 구분점(·)으로 잇고 **카드로 만들지 않는다.**
  박스를 씌우면 높이만 먹고 읽는 속도는 안 는다.
* 왼쪽 끝 로고는 **첫 화면으로 돌아가는 구멍**이다.
* **누가 로그인해 있는지를 왼쪽 위에 크게 둔다.** 참고 화면(슬라이드 1)이
  왼쪽 위에 `☰ 세나윤의원  ⊙ 백지영님` 으로 **병원 이름과 사람을 나란히**
  놓는다. 우리도 같게 한다 — `◈ EMPATHO │ 미래 대학병원 │ [박]박지훈님 · 유방외과`.
  이름 15px 700, 과 12px 회색, 동그라미 30px. 누르면 내 정보로 간다.
  ⚠ **오른쪽 끝에 작게 두지 않는다.** 지금 누구로 들어와 있는지는
  판독을 확정하고 결정을 남기는 사람이 매번 확인해야 하는 값이다.
  오른쪽에는 **시각과 알림만** 남긴다.
  ⚠ **과 줄에 두지 않는다.** 권한이 넓은 계정은 그 줄이 탭으로 다 찬다.
* 「오늘의 현황」은 **과를 가로지르는 첫 탭**이다. 내 과 화면은 그 옆이다.

**눈에 띄게 만드는 방법 — 색이 아니라 무게와 움직임으로**

색을 늘리면 판독 영상 위 병변 표시와 싸운다(9장). 그러니 존재감은 다른
것으로 낸다.

* **미끄러지는 강조선.** 아래 3px 선을 탭마다 따로 그리지 말고 **하나만**
  두고, 고른 탭의 위치·너비로 `transform: translateX()` 와 `width` 를
  옮긴다(180ms, `cubic-bezier(.2,.8,.2,1)`). 과를 바꿀 때 선이 미끄러져
  간다 — 어디로 갔는지가 눈으로 따라와진다.
  탭 글자 길이가 과마다 다르니 위치는 `ResizeObserver` 로 다시 잰다.
  ⚠ `aria-current="page"` 는 그대로 둔다. 선은 장식이고 상태는 속성이 말한다.
* **고른 탭은 바탕까지 바꾼다.** 선 하나로는 약하다. 글자를 흰색 700,
  탭 바탕을 한 톤 밝게(띠보다 밝은 회색), 건수 배지는 **반전**시킨다
  (흰 바탕에 검은 글자). 안 고른 탭은 회색 500.
* **얹으면(hover) 바탕이 옅게 뜬다.** 120ms. 누를 수 있는 자리라는 신호다.
* **검색창은 포커스에서 넓어진다.** 420 → 560px, 바탕이 한 단 밝아진다.
  200ms. 제일 많이 하는 행동이라 눌렀을 때 화면이 반응해야 한다.
* **요약 줄은 숫자를 키운다.** 숫자 17px 600, 라벨 12px 회색.
  「오늘 접수 **24**」가 아니라 「**24** 오늘 접수」로 숫자를 앞에 둔다.
  훑을 때 눈이 숫자만 따라간다.
* **로고 옆에 병원 이름**, 그 사이에 1px 세로선. 로고만 있으면 띠가 빈다.
* ⚠ **`prefers-reduced-motion` 을 존중한다.** 그 설정이 켜져 있으면 위
  움직임을 전부 끄고 즉시 바뀌게 한다. 판독실에서 하루 종일 보는 화면이다.
* 움직이는 것은 여기까지다. **자동으로 도는 것, 번쩍이는 것, 소리는 없다.**

### 4.2 환자 띠

환자 한 명을 다루는 화면이면 무조건 상단바 바로 아래에 온다.

```
[김] 김서연  54 · 여  P-2024-0417 │ [조영제 알레르기] [항응고제] │ ── 직전 2026-03-12 US · BI-RADS 3 │ 담당 최민호 교수 │ 환자 상세
```

* 경고칩은 **있을 때만** 나온다. 값이 없으면 칩 자체가 없다 — `undefined`
  를 「없음」으로 찍지 않는다.
* 얹는 화면: 업로드 · 판독 · 판독 정정 · 검사 종합 · 수술 결정.
* 환자 화면을 열 때 「최근 본 환자」에 기록한다.
* ⚠ 이 띠가 세로를 먹는다. 판독 화면 뷰어가 잘리지 않게 `--v-min-h` 를
  같이 조정하거나 띠를 접을 수 있게 한다. 둘 중 하나를 택해 토큰에 반영한다.

### 4.3 네 가지 상태 — 모든 목록·상세가 갖춰야 한다

| 상태 | 무엇을 보여주나 |
|---|---|
| 불러오는 중 | 자리를 지키는 뼈대. 화면이 통째로 사라지면 안 된다 |
| 비었음 | 왜 비었는지 + 다음에 할 일. 「검체가 없습니다」가 아니라 「접수 대기 중인 검체가 없습니다」 |
| 오류 | 무엇이 실패했는지 + [다시 시도]. 빈 목록으로 위장하지 않는다 |
| 권한 없음 | 「이 화면은 ○○ 권한이 필요합니다」 + 누구에게 말하면 되는지 |

**자동 새로고침이 도는 화면(큐)은 조용히 다녀온다.** 목록이 몇 초마다
사라졌다 돌아오면 읽던 중에 화면이 깜빡인다. `useApi` 의 `reload(true)` 가
그것이다.

### 4.4 히스토리 레일 — 왼쪽에 과거, 오른쪽에 지금 쓰는 것

참고 화면(오름차트 진료실)의 핵심이 이것이다. **왼쪽에 이 환자의 지난
기록이 날짜로 쭉 있고, 하나를 누르면 그 기록이 가운데에 펼쳐진다.**
쓰는 칸은 오른쪽에 있어서, **과거를 보면서 지금 것을 쓴다.**

```
┌──────────────┬─────────────────────────┬──────────────────────┐
│ 최신순  ▾    │ 진료기록 [2026-03-12]    │ 지금 쓰는 것          │
│              │                         │                      │
│ 2026.03.12   │ 접수메모  좌측 멍울 3주  │ 증상                 │
│  초 주 💊 🖼  │ ─────────────────────── │ [                  ] │
│ 2025.09.02   │ 신체계측 / 바이탈        │                      │
│  재 주       │ ┌────┬────┬────┐        │ 소견                 │
│ 2023.05.08   │ │ 혈압│ 체중│ …  │        │ [                  ] │
│  초          │ └────┴────┴────┘        │                      │
│              │ 소견 · 판독 · 처방       │ [임시 저장] [확정]    │
└──────────────┴─────────────────────────┴──────────────────────┘
```

* **왼쪽 레일** — 날짜만 크게, 그 아래 **그날 무슨 일이 있었는지 작은 기호**로
  (초진/재진 · 검사 · 판독 · 결정 · 추적). 참고 화면이 `초 주 💊 🖼` 로 찍던
  자리다. 우리는 글자 한 자씩 쓴다 — `접 문 촬 AI 판 결`.
  **색을 쓰지 않는다.** 있었으면 진하게, 없었으면 흐리게.
* **누르면 가운데가 그 날짜로 바뀐다.** 화면을 옮기지 않는다 — 쓰던 글이
  날아가면 안 된다.
* **맨 위는 항상 「지금」**이다. 과거를 보다가 돌아올 곳이 분명해야 한다.
* 정렬은 최신순이 기본. 「조회 목록 설정」처럼 종류를 걸러 볼 수 있게 한다.

**이 레일을 쓰는 화면**

| 화면 | 왼쪽 레일 | 가운데 | 오른쪽 |
|---|---|---|---|
| 환자 상세 | 전체 히스토리 | 고른 기록 | 리포트 · 추적 · 동의 |
| 영상 판독 | **이 환자의 지난 검사** | 뷰어(원본+AI) | BI-RADS · 소견 입력 |
| 병리 판독 | 지난 검체 | 뷰어 | B분류 · 소견 입력 |
| 간호 문진 | 지난 문진 | 고른 문진 | 오늘 문진 입력 |
| 검사 종합 | 지난 결정 | 영상 + 병리 | 결정 입력 |

**판독 화면에서 특히 중요하다.** BI-RADS 판독은 **이전 검사와 비교**하는
것이 본체다. 왼쪽에서 2026-03 을 누르면 그때 영상과 그때 판정이 옆에 뜨고,
「8mm → 12mm」가 눈에 보여야 한다. 지금은 그 비교를 하려면 화면을 나갔다
들어와야 한다.

**서버**
* `GET /patients/{id}/timeline` — 레일의 날짜와 기호가 여기서 나온다
* 누른 기록을 펴는 건 그 종류의 상세 경로로:
  `/studies/{id}/` · `/specimens/{id}/` · `/assessments?study=` · `/reports/{id}/`
* ⚠ **먼저 확인할 것** — timeline 의 각 이벤트에 **대상 id 와 종류가 실려
  오는가.** 안 오면 눌러도 무엇을 열지 알 수 없다. 없으면 백엔드에
  `kind` · `ref_id` 두 칸을 더해 달라고 요청한다(8장에 적어 둘 것).

### 4.5 부품

* **쪽 머리** — **빵부스러기와 제목뿐이다.** 「원무과 › 접수」 위에
  「접수」. 그게 전부다.
  **부제를 달지 않는다** — 「환자를 찾아 접수하면 간호 큐로 넘어갑니다」
  같은 줄은 처음 한 번 읽고 나면 하루에 수백 번 자리만 먹는다.
  제목도 늘리지 않는다 — 「접수 · 방문 환자 모니터링」이 아니라 **「접수」**.
  메뉴에 적힌 이름과 같아야 사람이 어디 있는지 안다.
* **카드** — 흰 바탕 · 1px 헤어라인 · 아주 옅은 그림자. 제목 줄 + 본문.
  ⚠ **카드는 성격이 다른 것을 가를 때만 쓴다.** 5.1 의 「박스로 나누지
  말 것」은 메인 화면만이 아니라 **업무 화면에도 그대로 간다.**
  같은 성격의 덩어리를 나란히 놓을 때는 **1px 선으로만** 가른다 —
  테두리 · 모서리 둥글리기 · 그림자를 겹쳐 쓰면 덩어리마다 안쪽 여백이
  또 생기고, 그 여백을 다 합치면 뷰어가 앉을 자리가 없어진다.
  판독 · 검사 종합처럼 뷰어가 있는 화면에서 특히 그렇다.
* **스크롤은 한 칸에 하나.** 칸 안에 스크롤 영역을 여러 개 만들지 않는다.
  둘이 겹치면 사람이 어느 것을 굴려야 할지 모르고, 굴려도 조금씩만
  움직인다. 리포트처럼 이어 읽는 글은 **한 덩어리로 이어 놓고 스택 전체를
  한 번에** 굴린다. 블록 머리가 필요하면 `position: sticky` 로 붙여
  지금 어디를 보는지만 남긴다.
  ⚠ 길다고 블록마다 `overflow-y: auto` 를 걸지 말 것. 그러면 블록 하나에
  두세 줄만 보인다 — 읽을 수 없는 화면이 된다.
* **뷰어에는 최대 높이를 씌우지 않는다.** 판독실 모니터는 1440 이상이다.
  화면이 남는데 `clamp()` 상한이나 `height: 680px` 같은 고정값 때문에
  안 자라면, 그 자리에서 잃는 것이 진단 정보다. 최소 높이만 정하고
  위는 열어 둔다.
* **표** — 판독실에서 훑어보는 자리다. 줄 높이를 키우지 말고 촘촘하게.
  고른 줄은 왼쪽에 굵은 선.
* **칩** — 상태를 말한다. 색을 늘리지 말고 채움/외곽선/점으로 가른다.
* **버튼** — 전부 알약 모양. **시안 채움은 한 화면에 하나**, 그 화면에서
  할 일 하나를 가리킨다.
* **팝업** — 뒤를 어둡게 깔고 가운데 카드. 제목 + 한 줄 설명 + 본문 +
  아래 버튼 줄. Esc 와 바깥 누르기로 닫힌다. **되돌릴 수 없는 동작은
  기본 초점을 취소에 둔다.**

## 5. 메인 화면 — 「오늘의 현황」

**박스를 늘어놓지 않는다.** 카드 여섯 개를 격자에 까는 대신,
**환자가 지나가는 단계마다 세로 칸(섹션)을 하나씩** 둔다. 칸이 화면 높이를
꽉 채우고, 그 안에서 목록이 스크롤된다. 그래야 빈틈이 안 생기고
**환자의 흐름이 왼쪽에서 오른쪽으로 읽힌다.**

### 5.1 뼈대

```
오늘 접수 24 · 진행 중 11 · 판독 대기 7 · 오늘 확정 9 · 확인 필요 3
┌───────────┬───────────┬───────────┬───────────┬───────────┬──────────┐
│ 접수·대기 6│ 검사 중 4 │ AI 분석 2 │ 판독 대기7│ 결정 대기 3│ 오늘 종결9│
│           │           │           │           │           │          │
│ [환자 줄] │ [환자 줄] │ [환자 줄] │ [환자 줄] │ [환자 줄] │ [환자 줄]│
│ [환자 줄] │ [환자 줄] │           │ [환자 줄] │ [환자 줄] │ [환자 줄]│
│ [환자 줄] │           │           │ [환자 줄] │           │          │
│     ⋮     │     ⋮     │           │     ⋮     │           │    ⋮     │
└───────────┴───────────┴───────────┴───────────┴───────────┴──────────┘
```

* 칸과 칸 사이는 **1px 선**이다. 카드처럼 그림자를 주고 띄우지 않는다.
* 칸 머리 = **이름 + 건수**. 오른쪽에 필요한 정렬·필터만 아주 작게.
* 칸 안은 목록이 이어진다. 높이가 모자라면 **그 칸만** 스크롤된다.
* 내 과에 해당하는 칸은 **살짝 밝게** 해서 어디를 봐야 하는지 알려 준다.

### 5.2 환자 줄 — 한 줄에 최대한 담는다

참고 화면이 한 줄에 열 가지를 담는다. 우리도 그렇게 한다.

```
김서연  건강보험  [조영제 알레르기]                          14:27  [집기]
P-0012 · 1972.05.08 · 54세 · 여 · 재진
MG ●   US ●   MRI ○   PATH ○                              ← 검사 진행
```

* **첫 줄** 이름(굵게) · 구분 칩 · 경고 뱃지 · 오른쪽에 시각과 동작 버튼
* **둘째 줄** 환자번호 · 생년월일 · 나이 · 성별 · 내원 구분 — 작고 흐리게
* **셋째 줄 = 검사 진행 점.** 네 모달리티를 `●`(끝남) `◐`(진행 중)
  `○`(안 함)로 찍는다. **색을 쓰지 않는다** — 채움 정도로만 가른다.
  이 한 줄이 「이 환자가 어디까지 왔는가」를 통째로 말해 준다.
* 줄을 누르면 **환자 상세**로. 버튼을 누르면 그 자리에서 동작한다(집기·호출·접수).

### 5.3 칸은 과마다 다르다

| 과 | 칸 (왼쪽 → 오른쪽) |
|---|---|
| 접수·간호 | 접수 대기 · 예약 신청 · 내원 대기 · 문진 중 · 배정 대기 · 검체 확인 · 추적 예정 |
| 영상 | 촬영 대기 · 업로드 중 · AI 분석 중 · 판독 대기 · 내가 집은 것 · 오늘 확정 |
| 병리 | 접수 대기 · 슬라이드 준비 · AI 분석 중 · 판독 대기 · 내가 집은 것 · 오늘 확정 |
| 유방외과 | 내 환자 대기 · 검사 진행 중 · 결과 도착(결정 대기) · 불일치 · 수술 예정 · 오늘 종결 |

「오늘의 현황」 탭(과를 가로지르는 화면)은 **과 칸 대신 단계 칸**을 쓴다 —
접수 → 문진 → 촬영 → 분석 → 판독 → 결정 → 종결. 병원 전체가 지금 어디에
몰려 있는지 한 장으로 본다.

### 5.4 「진료실 현황」 = 유방외과 선생님별 칸

참고 화면은 접수가 끝나면 **진료실마다 칸이 하나씩** 생긴다 —
`진료실1 · 백지영 내과 | 진료실2 · 김다영 내과`. 칸 머리에 지금 진료 중인
환자가 있고, 아래로 그 방의 대기 줄이 이어진다.

우리는 진료실이 아니라 **유방외과 선생님**이 그 단위다. 접수·배정이 끝나면
환자는 주치의에게 붙으므로, 칸 하나가 곧 한 선생님의 큐다.

```
┌──────────────────────────┬──────────────────────────┬──────────────────┐
│ 최민호 교수          대기 4│ 서나영 교수          대기 3│ 아직 배정 안 됨 2 │
│ 진료 중 · 김서연 P-0417   │ 진료 중 · 없음            │                  │
│ ─────────────────────────│ ─────────────────────────│ ─────────────────│
│ [환자 줄]                 │ [환자 줄]                 │ [환자 줄]         │
│ [환자 줄]                 │ [환자 줄]                 │ [환자 줄]         │
└──────────────────────────┴──────────────────────────┴──────────────────┘
```

* 칸 머리 = **선생님 이름 + 대기 건수**, 그 아래 **지금 진료 중인 환자** 한 줄.
  없으면 「진료 중 · 없음」이라고 적는다 — 빈칸으로 두지 않는다.
* 맨 오른쪽에 **아직 배정 안 된 환자** 칸을 둔다. 간호가 여기서 끌어다 넘긴다.
* 이 묶음을 쓰는 화면
  - **접수·간호 홈** — 배정이 주 업무다. 여기가 제일 크게 들어간다.
    접수한 환자가 어느 선생님께 갔는지도 같은 자리에서 보인다
  - **유방외과 홈** — 내 칸이 먼저 오고 다른 선생님 칸은 접어 둔다
* **서버는 그대로 쓴다**
  - 선생님 목록 `GET /staff?role=surgery` (이미 있다 — `nursing.surgeons()`)
  - 선생님별 환자 `GET /patients/?primary_staff=<id>&status=waiting`
    ⚠ `primary_staff` 에 `"me"` 를 넣는 건 확인됐다. **id 를 넣는 것도 되는지
    먼저 확인하고**, 안 되면 전체를 받아 화면에서 선생님별로 나눈다
  - 배정 `PATCH /patients/{id}/ {primary_staff: <id>}` (이미 있다)
* ⚠ 참고 화면의 「평균 대기 140분」은 **우리에게 없는 값**이다. 칸 머리에는
  대기 건수만 적는다.

### 5.5 과마다 배치가 다르다 — PDF 그 쪽을 그대로 따른다

**이 절을 추측으로 짜지 말 것.** `docs/EMPATHO 병원 웹 재구성.pdf` 에
과별 홈이 그려져 있다. **그 쪽을 열어 그대로 옮긴다.**

| 과 | PDF | 모양 |
|---|---|---|
| 원무 | **8쪽** | 칸 다섯을 가로로 나열 |
| 간호 | **12쪽** | 3단 격자 |
| 영상 | **17쪽** | — |
| 병리 · 유방외과 | 없음 | 가장 가까운 과의 쪽을 쓴다 |

**간호 12쪽이 제일 꽉 차 있다. 기준으로 삼는다.**

```
간호과  2026-09-21 (월)                    [내원 대기 화면 →] [문진·배정]
최근 본 환자  [환자31 문진 작성] [환자25 호출] …   내 계정으로 연 환자만
┌─ 왼쪽 1.5fr ──────────┬─ 가운데 1fr ──────┬─ 오른쪽 330px ┐
│ 내원한 대기 환자 5     │ 오늘 한 일        │ 2026년 9월     │
│  1 환자11 51·여 재진…  │  14:05 ● …        │  (달력·점 표시)│
│  2 환자18 66·여 신환…  │  13:48 ● …        ├───────────────┤
├───────────────────────┤───────────────────┤ 할 일 2개 남음 │
│ 확인이 필요한 것 3     │ 인계 사항  [남기기]│  ☐ …          │
│  [바인딩] … 2건        │  07:30 야간 한지원 │  ☑ …          │
│  [콜] … 1건            │  …                │  [메모지]      │
└───────────────────────┴───────────────────┴───────────────┘
```

* **인계 사항은 가운데 칸 아래**다. 「오늘 한 일」 바로 밑에 붙는다.
  오른쪽 끝이 아니다. 그 과 전체가 보는 교대 메모이지 환자 기록이 아니다.
* **할 일은 오른쪽**, **달력 아래**다. 내 것만 보이고 체크·추가·삭제한다.
* **달력이 오른쪽 맨 위**다. 예약 방문과 추적 콜 예정을 점으로 찍는다.
* ⚠ **칩 줄은 두지 않는다.** 목업에는 있지만 그건 목업 상단바가 52px
  한 줄이라 그 과 화면으로 가는 길이 칩뿐이었기 때문이다. 우리는 4.1 의
  **화면 줄(3층)** 이 그 일을 한다. 칩을 또 두면 같은 링크가 한 화면에
  두 번 있고, **내비게이터가 둘로 보인다.**
  같은 이유로 요약 줄 오른쪽에도 화면 줄에 있는 곳으로 가는 버튼을
  두지 않는다. 거기 남는 것은 **주 동작 하나**뿐이다.
* **확인이 필요한 것** — 왼쪽 칸 아래. 종류 태그 + 문장 + 건수.
* ⚠ 할 일과 인계는 지금 이 브라우저에만 남는다(8장 2번).

**폭은 `minmax(0,1.5fr) minmax(0,1fr) 330px` 이다.** 앞서 45/30/23 이라고
적었던 것은 1440 에서 잰 값이고, 목업은 **오른쪽만 고정폭**이다
(`docs/mockup/NursingHome.html`). 그래서 화면이 넓어질수록 오른쪽 비율은
줄어든다 — 1920 에서 49/33/18 이 되는 것이 맞다. 달력과 할 일은 넓어져도
쓸모가 안 느는 칸이라 고정이 맞다. **비율로 바꾸지 마라.**

**아래 칸은 윗변이 아니라 아랫변이 맞는다.** 단마다 늘어나는 칸이 하나씩
있고(주 큐 · 오늘 한 일 · 할 일) 나머지는 내용만큼만 높다. 위 칸 높이가
다르니 아래 칸 윗변은 원래 어긋난다 — 목업도 그렇다.

**내용이 적으면 칸을 늘리지 않는다.** 단 높이를 꽉 채우려고 칸을 늘이면,
환자가 셋일 때 칸의 3분의 2가 빈다. 칸은 **내용만큼만** 높고 남는 세로는
그냥 둔다. 세 단의 아랫변이 안 맞아도 괜찮다 — 자료가 차면 저절로 맞는다.
**빈 상자가 큰 것이 줄 안 맞는 것보다 나쁘다.**
최소 높이만 정해 둔다(머리 + 다섯 줄 정도). 그보다 적으면 그만큼만.

**여백을 남기지 않는다.** PDF 는 빽빽하다. 0건인 칸이 화면 폭 절반을
먹고 있으면 그건 배치가 틀린 것이다 — 빈 칸은 좁게 고정하고 남는 폭은
내용 있는 칸이 가져간다.

### 5.6 그 밖에

* **최근 본 환자** — 칩 줄 아래 한 줄로. 여덟 명까지, **내가 연 것만.**
  ⚠ **브라우저에 남기지 않는다.** 판독실 PC 는 공용이고 `localStorage` 는
  로그아웃해도 남는다. 화면이 살아 있는 동안만 메모리에 들고, 새로
  고치면 사라진다 — 안 남는 것이 기능이다.
* **오늘 한 일** — ⚠ 서버에 없다(8장 1번). 자리를 만들어 두고 비운다
* **새로 고침** — 칸 목록은 몇 초마다 조용히 다시 불러온다. 깜빡이면 안 된다
* **⚠ 「몇 분 기다렸는지」는 쓰지 않는다.** 참고 화면에는 「평균 대기 140분」
  「165′」 같은 것이 있지만 **우리 서버는 그 값을 주지 않는다.**
  요청 시각(14:27)만 적는다

## 6. 화면별

### 6.1 접수·간호 — 원무과와 간호과를 한 과로 합친다

**왜 합치나.** 접수 → 내원 대기 → 호출 → 문진 → 유방외과 배정은 실제로는
환자 한 명을 이어서 다루는 한 줄인데, 지금은 중간에 과 탭을 건너뛰어야
한다. 작은 검진 기관에서는 같은 사람이 둘 다 하기도 한다.

**권한은 한 줄도 안 바꾼다.** `perm.js` 맨 위에 적힌 대로 화면은 직책이
아니라 `perms` 배열만 본다. `reception.*` 열세 개와 `nursing.*` 다섯 개를
그대로 두고, 원무 일만 하는 사람에게는 `reception.*` 만 준다 — 그러면
그 사람 메뉴에서 간호 화면이 알아서 빠진다. `specimen.bind` 가 이미
과에 안 묶인 단독 권한으로 있는 것과 같은 방식이다.

**화면은 여섯 줄이다** — 홈 · 접수 · 내원 대기 · 환자 목록 · 예약 판 ·
추적 관리. 예약 신청 확인은 화면을 따로 두지 않고 **예약 판 안의 탭**으로
넣는다. 둘 다 예약이고, 신청은 「앱에서 들어온 것」일 뿐이다.
일곱 줄이 되면 내비게이터 둘째 줄(4.1)이 꽉 찬다.

⚠ 과 key 는 `nursing` 을 쓰고 이름만 「접수·간호」로 단다. 주소가 바뀌는
것은 원무 쪽 네 화면뿐이다.


**접수** — 환자를 찾아 접수하면 간호 큐로 넘어간다.
검사 종류는 **정하지 않는다** — 의학적 판단이라 유방외과 몫이다.
신환이면 등록부터. 오늘 현황을 접수 순서대로 같이 보여 준다.

**환자 목록** — 검색(`?q=` 를 주소에서 읽는다) · 정보 수정.
줄 끝에 [예약] 을 둔다 — 누르면 아래 예약 판이 **그 환자가 채워진 채로**
열린다. 목록 안에서 예약을 잡지 않는다.
⚠ 이름·생년월일·전화는 여기서 못 고친다(다른 표에 있다). 고칠 수 있는 것은
성별 · 출생연도 · 알레르기 · 주치의다.

#### 예약 판 — `/hospital/reception/reservations`

지금은 예약이 환자 목록 안에 얹혀 있다. **달력이 본체인 화면으로 뺀다.**
참고 화면(오름차트 예약)과 우리 **검체 등록 팝업**이 같은 모양이다 —
**왼쪽에 무엇을 볼지, 가운데에 이미 있는 것, 오른쪽에 지금 쓰는 것.**
4.4 히스토리 레일과 같은 규칙이고, 예약 판도 그 셋으로 짠다.

**칸은 사람이다.** 참고 화면은 「김다영(내과)」처럼 의사 한 명이 달력 한
칸이었다. 우리는 **예약 자체에 담당의 칸이 없다** — `POST
/exam-orders/schedule` 이 받는 것은 `patient_id` 와 `scheduled_at` **둘뿐**
이다. 그래서 **환자의 주치의(`primary_staff`)로 묶는다.** 주치의가 아직
없는 환자는 맨 아래 **「미배정」** 칸에 모은다. 서버에 칸을 새로 만들지
않는다. 5.4 진료실 현황과 같은 묶음이라 두 화면이 따로 놀지 않는다.

* **왼쪽** — 달 달력 둘(이번 달·다음 달)과 「보는 사람」 체크 목록. 체크를
  끄면 그 칸이 접힌다. 색 점은 **사람을 가르는 점 하나뿐** — 예약 덩어리를
  통째로 칠하지 않는다(1.3 · 9장).
* **가운데** — 일/주/월. 기본은 주. 세로는 08:00–18:00 을 30분으로 끊는다.
  덩어리 안에 **시각 + 이름**. 오늘 열은 배경을 아주 옅게. 날짜 머리에
  그날 건수를 적는다(`21(월) 3건`) — 세어 보면 나오는 숫자라 지어낸 값이
  아니다.
* **빈 칸을 누르면** 오른쪽 「새 예약」에 그 날짜·시각이 들어간다.
  **덩어리를 누르면** 오른쪽이 그 환자로 바뀐다. **화면을 옮기지 않는다.**

**오른쪽 — 예약 정보**

* **안 오신 적** — 참고 화면의 「부도이력」 자리다. 지난 예약인데 내원
  기록이 없는 것(`scheduled_at` 이 지났고 `visited_at` 이 빈 것)을 센다.
  ⚠ **「부도」라고 쓰지 않는다.** 창구에서 내원을 안 찍었을 수도 있어
  단정할 수 없다. **횟수와 날짜만 보이고 판단은 사람이 한다.**
* **지난 예약** — 상태 · 날짜 · 담당의 · 종류. `ordersOf(patient)` 하나면
  된다. **종류는 유방외과가 정하기 전까지 「미정」**이라고 쓴다 — 빈 칸으로
  두면 자료가 없는 건지 아직 안 정한 건지 모른다.
* **빠른 날짜** — 참고 화면의 `1주 2주 … 12주` 자리다. 유방 쪽은 간격이
  달라 **`1주 2주 4주 · 3개월 6개월 12개월 24개월`** 로 둔다. BI-RADS 3
  추적이 6·12·24개월이라 그 셋이 제일 많이 눌린다. 누르면 오늘부터 그만큼
  뒤가 날짜 칸에 들어가고 **달력도 그 주로 따라 움직인다.**
* **겹치면 그 자리에서 말한다** — 같은 환자가 같은 날 이미 예약이 있으면
  저장 전에 알린다. 위 「지난 예약」에 이미 다 있으니 새로 부를 것이 없다.
* **메모 칸은 아직 내지 않는다.** `schedule` 이 두 칸만 받아서 쓴 글이
  그냥 버려진다. 칸을 만들어 놓고 버리는 것이 제일 나쁘다(1.3).
  `staff_note` 가 생기면 그때 낸다(8장 2번).
* **만든 예약을 화면에서 못 지운다** — 취소·변경 경로가 서버에 없다.
  그 사실을 화면에 한 줄로 적어 둔다(8장 7번).

**다음 예약은 끝나는 자리에서 건다.** 참고 화면의 자막이 「수납과 동시에
다음 진료 예약」이다. 우리는 수납이 없으니 그 자리가 **종결**이다 —
간호 종결과 유방외과 종결 팝업에 **[다음 예약]** 을 두고, 누르면 이 판이
그 환자와 권장 간격(추적이면 6개월)이 채워진 채로 열린다.

**서버 — 새로 만들 것이 없다**

```
GET  /exam-orders?scheduled_from=…T00:00:00&scheduled_to=…T23:59:59
                 &ordering=scheduled_at          달력   reception.schedule()
GET  /exam-orders?patient={id}&ordering=scheduled_at
                                                 지난 예약  reception.ordersOf()
POST /exam-orders/schedule {patient_id, scheduled_at}   예약  reception.reserve()
GET  /staff?role=surgery                         칸 머리(사람)
```
⚠ 끝 경계에 **시각을 붙여야 한다.** `scheduled_to=2026-09-30` 은 서버에서
「30일 00:00」이 되어 **그날 예약이 통째로 빠진다.** `api.js` 주석 참고.

**예약 확인** — 앱으로 들어온 신청에 날짜와 시간만 정해 준다.
확정하면 위 예약 판의 그 주로 옮겨 간다 — 확정 뒤 [예약 판에서 보기] 를 둔다.
⚠ 지금 서버는 `confirm` 에 `modalities` · `exam_purpose` · `ordered_by` 를
**필수로** 받는다. 팀 결정(「원무는 날짜만」)과 반대라 고쳐질 예정이고,
그때까지 이 호출은 목업에서만 돈다. 화면은 **날짜만** 받게 짓는다.

**내원 대기 · 배정** — 지금 와 있는 환자를 접수 순서대로. 호출하고,
문진을 받고, 유방외과 의사에게 넘긴다. 검체 연결 팝업도 여기서 연다.
접수 화면에서 [접수하기] 를 누른 환자가 **화면을 옮기지 않아도** 여기
줄에 붙어야 한다 — 한 과가 됐으니 탭을 건너뛸 이유가 없다.

**추적 관리** — BI-RADS 3 확정 환자의 6·12·24개월 추적. 전화 기록을 남긴다.
추적 회차를 잡을 때 [예약] 을 누르면 예약 판이 6개월 뒤로 채워진 채 열린다.

### 6.2 영상의학과

**촬영 대기 큐** — 아직 아무도 안 집은 오더. **집으면 남의 화면에서
사라진다** — 그 사실을 화면에 적어 둔다.

**업로드** — 파일을 올리고 품질을 본다. 흔들렸으면 그 자리에서 반려해
촬영 대기로 되돌린다. 승인해야 AI 분석이 걸리고, 분석이 끝나야 판독이 열린다.
⚠ 업로드는 서버를 거치지 않고 저장소로 바로 간다(티켓 · Go 게이트웨이).

**판독** — 원본에 AI 오버레이를 얹어 보고 BI-RADS 를 매긴다.
초안 저장과 확정을 가른다. **확정은 교수만.** 확정하면 잠긴다.
이전 검사와 비교할 수 있어야 한다 — BI-RADS 판독의 핵심이다.

**전체 목록** — 지난 것까지. 여기서 정정으로 들어간다.

**판독 정정** — 먼저 **잠금 해제 팝업**이 뜬다. 사유를 받고
`unlock-status` 로 조건을 보여 준 뒤 `unlock` 을 부른다. 정정 화면은
원본과 정정본을 나란히 놓고, **원본은 지워지지 않는다**고 적는다.

### 6.3 병리과

영상과 화면 구조가 같다 — 큐 · 업로드 · 판독 · 전체 목록.
**다른 점 둘**
* 판독 단위가 검사가 아니라 **검체**다. 등급은 B1–B5.
* **정정 경로가 없다.** 확정은 한 번뿐이다(확정 사양서 §8-2). 확정
  팝업에서 그 사실을 분명히 말한다. 확정 후 오류는 새 검체로 처리한다.

### 6.4 유방외과

**내 환자** — 집는 절차가 없다. 주치의로 배정된 환자가 곧 큐다.

**검사 종합** — 영상과 병리를 **나란히** 놓고 본다. 둘의 일치 여부를
화면이 먼저 말해 준다. 여기서 촬영 요청 · 검체 등록 · 종결로 간다.

**검체 등록 — 팝업이다. 페이지로 만들지 않는다.**
검사 종합에서 손을 떼지 않고 등록해야 한다. 여는 자리는 둘 —
유방외과 **검사 종합**, 간호 **내원 대기**(검체 연결).
예약 판(6.1)과 같은 규칙으로 짠다: **왼쪽에 이 환자의 지난 검체, 오른쪽에
지금 쓰는 것.**

* **스스로 채워지는 칸** — 환자 · 검체번호(자동 발번) · 보낼 곳(병리과) ·
  표적 병변(영상 판독의 병변 목록에서 고른다) · 측 · 채취 일시(지금) ·
  시술자(로그인한 사람). 사람이 고르는 것은 **채취 방법**(CNB · VABB ·
  FNA · 절제) · **유도**(초음파 · 정위 · 촉지) · **개수** · 특이사항뿐이다.
  손으로 옮겨 적게 하지 않는다 — 옮겨 적는 자리가 곧 틀리는 자리다.
* **경고 띠는 환자 기록에서 나온다** — 항응고제 복용, 조영제
  알레르기(`contrast_allergy`). **화면이 지어내는 경고가 아니다.**
  근거가 없으면 띠를 띄우지 않는다(1.3).
* **라벨** — 등록하면 라벨이 나온다. 라벨이 검체와 맞는지 확인하는 것은
  **간호**고, 확인 전에는 병리로 넘어가지 않는다. 그 문장을 팝업에 적는다.
* 등록하면 병리 큐(`/specimens/queue`)에 뜬다. 그 자리로 보내지는 않는다 —
  유방외과는 검사 종합에 그대로 남는다.
* ⚠ **`POST /specimens` 가 아직 없다**(8장 5번). 생기기 전까지 팝업은
  화면만 돈다. 보낼 칸은 8장에 적어 두었다.

**수술 결정** — 결정 종류와 가부, 근거를 남긴다. 결정은 지워지지 않는다 —
바꾸려면 새 결정을 남긴다. 그 이력을 같은 화면에 보여 준다.
⚠ 판독문 저장(`PUT /reports/{id}/`)과 결정 기록(`PATCH
/assessments/{id}/decision`)은 **다른 호출**이다. 둘 다 쓴다.

**불일치 처분** — 영상 판정과 병리 확진이 갈린 건. 어느 쪽을 따를지 정한다.

### 6.5 환자 상세 — 모든 과 공통

과 바깥 주소(`/hospital/patients/:id`)다. 어디서 와도 같은 화면이다.

**왼쪽** 이번 방문의 진행 단계 · 병변 크기 변화(표) · 문진
**가운데** 전체 히스토리 — `GET /patients/{id}/timeline` 하나로.
날짜별로 묶고 종류 필터(접수 · 검사 · 판독 · 결정 · 추적)
**오른쪽** 이전 담당의 소견(최근 4건) · 리포트와 잠금 상태 · 추적 일정 · 동의

**이전 담당의 소견**이 이 화면의 핵심이다. timeline 의 판독·결정 이벤트에서
소견 문장을 뽑아 「2026-03-12 · 영상의학과 · 박지훈 교수 — …」로 보여 준다.
확정된 것만, 고칠 수 없다고 적어 둔다.

### 6.6 내 정보

프로필 · 소속 · 역할 · **내가 할 수 있는 일**(`me.perms` 를 사람 말로) ·
비밀번호 변경. 최근 로그인 기록은 서버에 없으니 칸을 만들지 않는다.

## 7. 실제로 쓰려면 이것도 있어야 한다

* **저장 안 된 것을 들고 나가려 하면 막는다** — 판독문을 쓰다 다른
  화면으로 가면 묻는다. 하루에 수십 번 쓰는 화면이라 한 번만 날려도 크다.
* **초안 자동 저장** — 판독 화면. 브라우저가 죽어도 글이 남아야 한다.
* **세션이 끊기면 알려 준다** — 토큰이 만료됐는데 저장 버튼이 그냥
  실패하면 안 된다. 다시 로그인하고 **하던 자리로 돌아온다.**
* **키보드로 큐를 넘긴다** — ↑↓ 로 줄 이동, Enter 로 열기. 마우스를
  덜 쓸수록 빠르다.
* **인쇄** — 판독 결과지는 종이로 나간다. `@media print` 로 상단바와
  버튼을 빼고 본문만 남긴다.
* **네트워크가 끊겼을 때** — 저장 실패를 조용히 삼키지 않는다. 다시
  시도할 수 있게 남겨 둔다.
* **화면 크기** — 판독실 모니터(1440 이상)가 기준이다. 1100px 아래에서는
  두 단이 한 단으로 접히는 정도까지만. **폰은 대응하지 않는다** —
  환자 앱이 따로 있다.

### 8.2 화면이 다 끝난 뒤에 만들 것

**지금 만들지 말 것.** 순서는 화면 → DB → 엔드포인트다.

1. **`GET /home?dept=`** — 홈 요약 한 방.
   「확인이 필요한 것」 건수 + 「오늘 한 일」 + 불일치 목록을 함께 준다.
   지금 홈이 목록을 서너 번 부르는 걸 한 번으로 줄인다.
   읽기 전용 뷰 하나 + `urls.py` 한 줄. **마이그레이션 없음.**

2. **`staff_note` 표** — 할 일 · 인계 · 메모지를 한 표로.
   `kind(memo|todo|handover) · dept · owner_id · body · patient_id · done ·
   pinned · shift_date · pos_x · pos_y` + 감사 4칸.
   `GET/POST /notes` · `PATCH/DELETE /notes/{id}`.
   화면 쪽은 **`lib/notes.js` 를 새로 만들어 그 뒤에 숨긴다** — 지금은
   localStorage 에 넣고(키 `${kind}:${dept}`), 표가 생기면 그 파일의
   `read`/`write` 두 함수만 바꾼다. 화면은 한 줄도 안 고친다.
   **예약 참고사항도 여기 얹는다** — `patient_id` 칸이 이미 있어서
   표를 또 만들 필요가 없다(6.1).

3. **문진표 세 칸** — `questionnaire/v1.yaml`
   ```yaml
   past_history:    { type: text, label: 과거력 }
   medications:     { type: text, label: 복용 중인 약 }
   outside_records: { type: bool, label: 타 병원 자료를 가져오셨습니까 }
   ```
   외부 자료는 **있는지 없는지만.** 알레르기는 환자에 `contrast_allergy`
   로 이미 있으니 문진에 또 넣지 않는다. 가족력 · 증상도 이미 있다.
   JSONB 면 마이그레이션도 필요 없다.

4. **불일치 목록** — `/discordances/{id}` 는 있는데 목록이 없다.
   1번 안에 같이 넣으면 된다.

5. ~~**검체 생성**~~ — **바로잡음 (09-21, 윤수용님 API 문서).**
   `POST /specimens/` 가 **이미 있다**(⚠ 슬래시 필수). 「없다」고 적었던 것은
   `hospital/api.js` 에 넣지 않았을 뿐이다. 검체 등록 팝업(6.4)은
   **서버를 기다릴 필요가 없다.** `api.js` 에 한 줄 더하면 된다.
   보낼 칸 — `patient_id · lesion_id · side · method · guidance ·
   core_count · collected_at · collected_by · note`.
   검체번호는 서버가 발번한다.

   **같이 확인한, 있는데 우리가 안 쓰는 경로 셋**
   * `POST /reports/final` — 종합 소견서 발급(유방외과만). 진료 종결에서 쓴다
   * `GET /reports/?patient={id}` — 환자 리포트 목록(⚠ 슬래시 필수).
     환자 상세(3묶음)에서 쓴다
   * `POST /exam-orders` — 재촬영 오더. `radiology.retake` 권한은 있는데
     부르는 곳이 없다

6. **예약 변경 · 취소** — `/exam-orders/{id}` 에 취소가 없다.
   `PATCH /exam-orders/{id}/cancel {reason}` 하나면 된다. **지우지 않는다** —
   상태만 바꾸고 기록은 남긴다(1.2). 생기기 전까지 예약 판(6.1)은
   「만든 예약은 여기서 못 지웁니다」라고 적어 둔다.

7. **나이와 성별 — 먼저 응답을 까 볼 것**
   나이를 세는 코드가 지금 세 곳에 따로 있고(`api.js` 의
   `normalizePatient` · `lib/PatientBar.jsx` · `screens/reception/Patients.jsx`)
   **셋 다 `올해 − birth_year` 라 만 나이가 아니다.** 생일이 안 지난
   사람은 한 살 많게 나온다. 검진 권고 연령을 눈으로 보는 화면이라
   한 살이 의미가 있다.
   ⚠ **검색·목록 응답에 `birth_date` 가 오는지 주석 셋이 서로 다르다**
   (`Intake.jsx:73` 은 온다고, `Register.jsx:172` 와 `Patients.jsx:146` 은
   `birth_year` 뿐이라고 적고 있다). `GET /patients/?q=…` 응답을 한 번
   까 보고 정한다 —
   * `birth_date` 가 온다 → 프론트가 만 나이로 센다. **계산은
     `normalizePatient()` 한 곳에만 둔다.**
   * 안 온다 → `PatientSerializer` 에 `age`(만 나이) 한 줄을 더한다.
     `/exam-orders` 는 이미 `age` 를 얹어 주므로 양쪽을 맞추는 일이다.
     마이그레이션 없음.
   정해지면 세 곳의 계산을 지우고, 그 **뒤에** `patient.birth_year` 를
   버린다. 순서를 뒤집으면 나이가 전부 빈칸이 된다.
   이름 없이 나이·성별만 쓰는 경로(AI 입력 · 집계)는 `patient_pii` 를
   직접 읽지 말고 나이만 계산해 주는 뷰를 쓴다.

8. **신환 등록에 성별** — 지금 `POST /patients/register` 가 받는 것은
   `name · birth_date · phone` 셋뿐이다(`Register.jsx:97`). 창구에서 만든
   환자는 **성별이 빈 채로** 간호로 넘어가고 나중에 환자 목록에서 따로
   고쳐야 한다. `PatientRegisterSerializer` 에 `sex` 를 필수로 더하고,
   등록 팝업에 라디오 한 줄을 넣는다. 앱으로 예약하고 온 환자는 이미
   값이 있으니 다시 받지 않는다.

9. **`/patients/today-status` 에 환자번호 · 나이 · 성별 · 시각** — 지금
   응답이 네 칸뿐이다(`exam_order_id · patient_id · patient_name · stage`,
   `core/views/reception.py` 의 `PatientTodayStatusView`). 원무 홈의 현황판
   칸(5.1)이 **이름과 진행 점만** 그릴 수 있고 둘째 줄이 통째로 빈다.
   `ExamOrderSerializer` 가 이미 `patient_number · age · sex · visit_type` 을
   계산해 주므로 그 네 줄을 여기에 옮겨 붙이면 된다. `visited_at` 도 같이.
   **마이그레이션 없음.**

10. **주치의로 거르기 — 세 군데가 한 이유로 막혀 있다**
    * `PatientViewSet.get_queryset()` 이 `primary_staff=="me"` 면
      `qs.filter(primary_staff=staff)` 로 **바로 돌아간다.** `status` 를
      안 봐서 `status=waiting` 과 `status=all` 이 같은 줄을 준다.
      유방외과 홈의 두 칸이 같은 목록이라 하나로 합쳤다(`dept/breast.jsx`).
    * 같은 `?primary_staff=` 가 **id 는 못 받는다.** 넣으면 그 갈래를 안 타고
      `status` 필터만 남아 남의 환자가 섞인다.
    * `ExamOrderQueryView` 에는 **주치의 조건이 아예 없다.** 받는 것은
      `status · visited · scheduled_on · scheduled_from/to · patient · ordering`
      뿐이고, 응답(`ExamOrderSerializer`)에도 `primary_staff` 가 없어
      전부 받아 화면에서 가를 수도 없다.

    두 뷰에 `primary_staff`(id 또는 `me`)를 받게 하고 `status` 를 한 번 더
    거르면 —
    * 유방외과 큐를 `/exam-orders` 로 받아 **시각 · 검사 진행 점**이 붙는다.
      지금 그 줄 오른쪽이 **421px 빈다**. 5.2 의 세 줄이 채워진다
    * **5.4 선생님별 칸**이 열린다. 지금은 못 만들어 빼 둔 상태다
    * 유방외과 홈의 두 칸을 도로 나눌 수 있다

    ⚠ **같이 볼 것** — `ExamOrderQueryView` 는 `OwnedOnly` 가 안 걸려 있어
    `ExamOrder.objects.all()` 이다. 로그인한 직원이면 **전 과의 오더를
    훑을 수 있다.** 필터를 더하는 김에 이 경계도 같이 정한다.

11. **timeline 이벤트에 `kind` · `ref_id`**
   눌러 그 기록을 열려면 «무엇의 몇 번인지»가 있어야 한다. 이미 실려 온다면
   할 일이 없다. **먼저 응답을 까 보고 판단할 것.** 유방외과 검체 등록이 여기 걸린다.

### 8.3 Redis · Celery · Go 는 건드리지 않는다

* **Go file-gateway** 는 파일이 서버를 거치지 않고 저장소로 가는 길이다.
  티켓 발급과 완료 콜백이 전부다.
* **Celery · Redis** 는 AI 분석처럼 오래 걸리는 일을 뒤로 넘기는 자리다.
* 위 열한 가지는 전부 **읽고 바로 답하는** 요청이다. 큐에 넣을 것이 없다.
  장고 뷰와 마이그레이션 한 개(2번)면 끝난다. 캐시도 필요 없다 —
  인덱스만 있으면 몇 밀리초다.

## 9. 하지 말 것

* `api.js` 에 새 경로를 추가하지 말 것. 필요하면 8장에 적는다
* `api.js` `perm.js` `codes.js` `tokens.css` 의 **주석을 지우지 말 것.**
  그 주석이 「왜 이렇게 되어 있는가」의 유일한 기록이다
* CSS 에 숫자를 직접 쓰지 말 것. 토큰을 먼저 만든다
* 색을 늘리지 말 것. 빨강·노랑·초록을 들이면 판독 영상 위에서 병변 표시와
  싸운다
* 줄바꿈을 건드리지 말 것 — 저장소가 CRLF 라 파일을 통째로 다시 쓰면
  diff 가 전부 바뀐 것처럼 나온다.
  확인은 `git diff --stat --ignore-all-space -- hospital/`
* 폰 화면을 맞추느라 시간을 쓰지 말 것. 환자 앱이 따로 있다
* **화면이 자기 사정을 설명하지 말 것.** 「서버가 이름·성별·나이를 주지
  않는 건은 —로 둡니다」 「고르면 오른쪽에서 불러옵니다」 같은 문장을
  화면에 쓰지 않는다. 병원 화면은 그런 말을 안 한다 — 미완성으로 보인다.
  값이 없으면 **그냥 `—`** 를 찍거나 아예 안 그린다. 왜 없는지, 어디서
  오는지, 다음에 무엇이 일어나는지는 **적지 않는다.**
  화면에 남는 설명은 두 가지뿐이다 —
  **되돌릴 수 없다는 경고**, 그리고 **안 눌리는 이유**(권한·선행 조건).
  그 둘은 사람이 실수하는 걸 막으니 남긴다.

## 10. 순서
