# 맘모그래피 파트 — 학습

초음파 파트와 같은 구조다. 동결된 MedSAM3 병합본 위에 LoRA 만 학습한다.

---

## 폴더

```
mammo/
  medsam3/     MedSAM3 연결 — 심볼릭 링크 5개, 공유 저장소를 가리킨다
  docs/        보고서 · 일지 · 발표용 확정 수치
  training/
    code/      현행 코드
    configs/   학습 설정
    ckpt/      학습 결과 (LoRA · 42MB)
    logs/      실행별 로그
  data/        det (구 축소본) · det_tile1008 (현행)
  runs/        det_run — 기준선(전체 미세조정) 결과
  archive/     끝난 갈래의 코드 · 로그 · 산출물
```

`medsam3/` 아래는 **절대 건드리지 않는다.** 링크가 끊기면 3.4GB 백본을 다시
받아야 한다. `cleanup.py` 가 어떤 인자로도 그쪽을 못 지우게 막아둔다.

경로는 `code/paths.py` 한 곳에서 정한다. 실행 위치(cwd)에 기대지 않고 파일
위치에서 거슬러 올라간다 — `import_medsam3` 가 `os.chdir` 를 하기 때문에
cwd 기준 경로는 반드시 깨진다.

---

## 두 시스템

| | 하는 일 | 입력 | 출력 |
|---|---|---|---|
| 검출기 | 병변 위치 찾기 | 유방 영상 | 박스 + 점수 |
| 서술어 시스템 | 성질 기술 → 등급 → 판단 | 병변 조각 | BI-RADS · 조직검사 여부 |

검출기는 서술어 시스템에 빠져 있는 첫 단계를 채우려고 붙인다. 현재 둘은
아직 연결되지 않았다.

---

## 검출기 — 돌리는 법

### 1. 데이터

```bash
python3 make_tiles.py --dry-run --jobs 8      # 타일 수와 용량만
python3 make_tiles.py --go --jobs 8
python3 verify_tiles.py                        # 화소 동일성 · 신호
```

원본 DICOM 을 **원본 해상도 그대로** 1008 타일로 자른다. 줄이지 않는다 —
줄이면 미세석회가 사라진다(아래 참조).

`verify_tiles.py` 는 타일과 원본의 같은 좌표를 화소 단위로 뺀다. **최대 차이
0** 이 나와야 한다.

### 2. 학습

```bash
python3 train_mammo_det.py --check            # 두 배치 · 기울기가 흐르는지
nohup python3 -u train_mammo_det.py --epochs 6 > /dev/null 2>&1 &
tail -f ../logs/latest.log
```

`--check` 를 반드시 먼저 돌린다. **LoRA 기울기 절대합이 0 이면** 이름만 LoRA
이고 아무것도 안 배운다. 몇 시간 뒤에 알아차리는 것보다 낫다.

로그는 셸 리다이렉트가 아니라 스크립트가 직접 `logs/train_<시각>.log` 에
쓴다. `> train.log` 로 넘기면 다음 실행이 앞 기록을 덮어쓴다.

### 3. 평가

```bash
python3 eval_mammo_det.py --check --lora ../ckpt/last_lora.pt
nohup python3 -u eval_mammo_det.py --lora ../ckpt/last_lora.pt \
  --save-json ~/workspace/breast/mammo/archive/outputs/tile_dets_last.json \
  > ../logs/eval_tile.log 2>&1 &
```

원본 DICOM 을 읽어 **유방 전체**를 타일로 훑고, 박스를 원본 좌표로 되돌려
NMS 로 합친 뒤 원본 영상 단위로 FROC 을 낸다. 영상당 약 31 타일, 598장에
약 83분.

학습용 타일(영상당 3.5장)로 평가하면 훑는 면적이 좁아 **오탐이
과소평가된다.** 그래서 중간 파일을 만들지 않는다.

`--save-json` 은 **절대경로로 준다.** 상대경로는 `os.chdir` 뒤에 다른 곳을
가리킨다.

## 지켜야 하는 것

**`num_workers` 는 0 이다.** 이 컨테이너의 `/dev/shm` 이 64MB 다. 워커를 쓰면
배치를 넘기지 못하고 **오류 없이** 멈춘다. 그 상태로 8시간을 날린 적이 있다.
데이터 대기는 배치 시간의 3% 라 잃는 것이 없다.

**입력은 1008 이다.** RoPE 표가 그 크기로 미리 계산돼 있다. 다른 값을 넣으면
순전파 도중 assert 로 죽는다. 창 어텐션 블록의 표(24²)와 전역 블록의 표(72²)가
다르므로, 크기를 확인할 때는 **큰 쪽**을 봐야 한다.

**범주 번호는 1=mass, 2=calcification 이다.** 어긋나면 평가기를 잘못 겨눴을
때 종류가 조용히 뒤바뀌어 그럴듯한 오답이 나온다.

**학습과 평가는 같은 LoRA 설정으로 모델을 세워야 한다.** 두 스크립트가
`configs/mammo_det.yaml` 을 `mammo_cfg.lora_args()` 라는 같은 함수로 읽는다.
설정 파일이 아니라 그 함수가 일치를 보장한다 — 잘못 읽어도 양쪽이 똑같이
잘못 읽는다. 명령줄로 준 값이 설정보다 우선한다.

**병합본은 분리형(`medsam3_merged.pt`)만 쓴다.** 통합형은 옛 하이드라 학습
전용이었고 지웠다. 이 경로에서는 어텐션 형식 불일치가 발생할 수 없다.

## 왜 타일인가

검출용 데이터를 만들 때 원본(긴 변 약 5,200px)을 1008로 줄였다. 5배 축소다.

| | 실제 크기 | 원본에서 | 축소 후 |
|---|---|---|---|
| 종괴 | 1~3cm | 200~600px | 40~120px — 덩어리로 남는다 |
| 미세석회 낱개 | 0.2~0.5mm | 4~10px | 1~2px — 사라진다 |

병변 자리와 같은 크기의 정상 조직을 비교해 작고 밝은 알갱이가 몇 배 더 많은지
쟀다.

| 단계 | 미세석회 | 종괴 |
|---|---|---|
| 원본 해상도 | x1.75 | x1.72 |
| 1008로 축소 | x1.12 | x1.59 |
| **원본 해상도 타일** | **x1.85** | x0.71 |

석회는 초과분의 84%를 잃고 종괴는 18%만 잃는다. 같은 백본이 서술어
시스템에서는 석회를 잘 다루는데(민감도 98.2%), 그쪽은 원본 해상도 조각을
받는다. **모델이 못 보는 것이 아니라 지워서 준 것이었다.**

종괴의 x0.71 은 정상이다. 종괴는 균질한 덩어리라 미세 질감이 주변 조직보다
적고, 신호가 알갱이가 아니라 밝기와 모양에 있다.

## 현재 성능

같은 598명 · 중심 명중 기준.

| 영상당 오탐 | 종괴 기준선 | 종괴 타일 | 석회 기준선 | 석회 타일 |
|---|---|---|---|---|
| 1.0 | 57.3% | 48.3% | 18.6% | **50.2%** |
| 4.0 | 61.3% | **75.0%** | 37.3% | **84.2%** |

기준선은 1008 축소 전체 영상 · 전체 미세조정 838M · 20에폭.
타일은 원본 해상도 타일 · 동결 + LoRA 11M · 6에폭.

**미세석회가 2.7배 올랐다.** 종괴는 낮은 오탐에서 내려가고 높은 오탐에서
올랐다 — 타일이 맥락을 잘라내는 대가이며, 최대 재현율은 61.3% → 75.0% 다.

기준선 mAP: 종괴 0.157 (AP50 0.370) · 석회 0.002 (AP50 0.008).
타일 모델의 mAP 는 아직 측정하지 않았다 — 검출 좌표계가 COCO 형식이 아니다.

### 어느 체크포인트를 쓰나

**`last_lora.pt` 다.** `best_lora.pt` 는 검증 손실로 골랐는데 그 기준이 틀렸다.

```
검증 손실   에폭 0  5.04 (최저)   →   에폭 5  7.15
검출 성능   에폭 0 이 전 구간 열세 (같은 200장 비교)
              석회 1FP  34.1% 대 48.9%
              종괴 1FP  34.4% 대 54.2%
```

손실에는 박스·분류·존재 여부가 섞여 있고 `presence_loss`(가중치 20 × 보조
단계 6개)가 대부분을 차지한다. FROC 은 박스 위치와 점수 순위만 본다.
**두 지표가 다른 것을 잰다. 손실로 모델을 고르면 안 된다.**

에폭 5 에서도 아직 개선 중이었으므로 더 돌리면 더 오를 가능성이 있다.
