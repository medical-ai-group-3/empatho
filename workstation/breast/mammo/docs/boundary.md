# 맘모 입출력 · Go 경계

2026-09-04 · 출처 `infer_mammo.py` · `serve_mammo.py` · `services/gosvc/`

응답 필드 단위 명세는 `docs/mammo_api.md`. **이 문서는 파트 사이 경계만 다룬다** — 좌표계·단위·식별자, Go 서비스 계약, 지금 어긋나 있는 것.

---

## 입력

**맘모그램 1장.** DICOM 또는 PNG. multipart `file`.

크기·비트깊이 무관 — 내부에서 백분위 절단(99.9)으로 uint8 로 맞추고, 조직 영역만 잘라 1008px 타일로 훑는다. **원본 크기와 자른 위치를 기억해뒀다가 결과 좌표를 원본 기준으로 되돌린다.**

요청마다 덮어쓸 수 있는 값 — `score_calc` · `score_mass` · `tissue_frac` · `topk`.

MONOCHROME1 이면 우리가 뒤집는다. **받는 쪽이 또 뒤집으면 안 된다.**

---

## 출력

최상위 구조만 적는다. 각 필드는 `mammo_api.md`.

| 키 | 타입 | 뜻 |
|---|---|---|
| `image` | object | 원본 크기 · `pixel_spacing_mm` · `tissue_bbox` |
| `dicom` | object | 헤더에서 그대로 읽은 값. PNG 입력이면 `{}` |
| `lesions` | array | 병변 목록. **빈 배열 가능** |
| `summary` | object | 최고 등급 · 조직검사 여부 · **기권 여부** |
| `detection` | object | 후보 몇 개가 어디서 잘렸는지 |
| `params` | object | 이번 요청에 실제로 쓴 값 전부 |
| `limitations` | object | 못 채우는 필드와 그 이유 |

**`lesions` 가 비어도 「정상」이 아니다** — `summary.abstained` 를 볼 것. 서술어 모델에 「소견 없음」 클래스가 없어서 검출이 0건이면 판정 자체를 못 한다.

**`lesion.kind` 를 신뢰하지 마라** — 종류는 분류 헤드가 아니라 텍스트 질의에서 나온다. 위치는 맞고 종류가 틀리는 경우가 있다.

## 좌표계 — 세 가지가 돌아다닌다

| 좌표계 | 원점 | 어디에 쓰이나 |
|---|---|---|
| **원본 화소** | 영상 좌상단 | 서빙 응답 `lesions[].box` · `image.tissue_bbox`. **외부로 나가는 건 전부 이것** |
| **조직 상자 기준** | `tissue_bbox` 좌상단 | 내부 검출 파일 — `tile_dets_*.json` · `merge_*.json` |
| **타일 기준** | 타일 좌상단 | 추론 내부에서만. 저장하지 않는다 |

```
원본 = 조직상자기준 + (cx0, cy0)
(cx0, cy0, cx1, cy1) = tissue_bbox(tissue_mask(norm8(arr, clip)), pad)
기본값 clip=99.9 · pad=32
```

**이 두 값이 다르면 원점이 달라진다.** 좌표를 주고받는 쪽은 `clip` 과 `pad` 도 같이 맞춰야 한다.

**실제 사고 (2026-09-03)** — `tile_dets_*.json` 을 원본 좌표로 알고 정답과 맞췄다. 조직 상자가 (0,0) 에서 시작하는 영상이 541/598 장이라 **대부분 맞아 보였고 57장에서만 어긋났다.** 최대 재현율이 0.949 대신 0.879 로 나왔고 원인 찾는 데 반나절이 들었다. 파트 사이 오류는 거의 다 이 모양이다 — 값은 건너가는데 좌표계 합의가 없고, 일부에서만 틀려서 발견이 늦다.

## 단위

| 값 | 단위 | null 가능 | 주의 |
|---|---|---|---|
| `ai_size_px` | 화소 | 아니오 | 박스 긴 변. AI 원본값 · 불변 |
| `ai_size_mm` | mm | **예** | `pixel_spacing_mm` 없으면 null. `ai_size_measurable` 로 확인 |
| `pixel_spacing_mm` | mm/화소 | **예** | CBIS 는 필름 스캔이라 태그 자체가 없다 (표본 120장 중 0장) |
| `score` | 0~1 | 아니오 | 종류마다 임계값이 다르다. **두 종류 점수를 한 줄로 세워 비교 금지** |
| `certainty` | Σ\|pᵢ−0.5\| | 아니오 | pᵢ 가 CORAL 경계 확률이 아니라 **서술어 축별 확률**. 초음파와 같은 τ 를 쓰면 안 된다 |
| MRI `evidence.frame` | — | 아니오 | `pixel` · `resampled_1mm` · `original`. 값이 없으면 해석 금지 |

**화소 간격은 한 값이 아니다** — VinDr 443장 실측에서 기종별로 갈렸다. `0.085` 355장 · `0.0814` 81장 · `0.0828` 4장 · `0.083` 3장. 서비스 경로는 영상마다 `ImagerPixelSpacing (0018,1164)` 를 읽는다. **상수로 박으면 안 된다.**

## Go 서비스

### 티켓 — 모든 요청의 입구

Django 가 발급하고 Go 가 검증한다. HS256 · 유효기간 5분 · nonce 는 한 번만.

| 클레임 | 뜻 | 안 맞으면 |
|---|---|---|
| `purpose` | 무엇을 하려는 티켓인가 | 403 |
| `patient_id` · `scope_id` | 대상 | 콜백에 그대로 실린다 |
| `max_bytes` | 허용 크기 | 받는 도중에 끊는다 |
| `content_type` | 허용 형식 | 415 |
| `object_key_prefix` | 쓸 수 있는 경로 | 403 |
| `exp` · `nonce` | 유효기간 · 재사용 방지 | 401 |

**nonce 가 프로세스 메모리에 있다** — Go 를 여러 개 띄우면 재사용 검사가 깨진다. 지금은 단일 인스턴스 전제. 수평 확장하려면 nonce 저장소를 밖으로 빼야 하고 Django 와 협의가 필요하다.

### 경로

| 서비스 | 경로 | purpose |
|---|---|---|
| file-gateway `:8091` | G-F1~F7 분할 업로드 | 업로드 계열. **원본 전용** |
| | `POST /svc/v1/derived` | `derived_upload` |
| | `GET /svc/v1/derived/{key...}` | `download` · `tile` |
| llm-proxy `:8090` | `POST /svc/v1/llm/report-narrative` | G-L1 |
| | `GET /svc/v1/llm/health` | — |
| notify `:8092` | G-N1~N5 (SSE) | 알림 계열 |

**파생물에 분할 업로드를 쓰지 않는다** — 3D 메시·마스크·타일은 `/svc/v1/derived` 로. DICOM 파싱도 Orthanc 전송도 안 한다.

**내려받기 경로를 따로 둔 이유** — 키만으로는 어느 버킷인지 알 수 없다. 한 경로에서 추측하게 두면 언젠가 엉뚱한 버킷을 뒤진다.

**소견 생성은 리포트 서버(:8002)에서 끝난다** — Ollama 를 직접 부르지 않는다. 리포트 서버로는 `{result, evidence:[id들]}` 만 보낸다.

**SSE 버퍼가 넘치면 `resync`** — 받으면 화면이 상태를 다시 조회해야 한다. 이벤트를 이어붙이면 안 된다.

### Django 로 가는 콜백

| 번호 | 언제 | 무엇을 만든다 |
|---|---|---|
| `I-1` | Garage 커밋 직후 | `storage_object` 행. **실패하면 업로드를 502 로 되돌린다** |
| `I-2` | DICOM 파싱 후 | 촬영 정보 + `orthanc_instance_id`. MRI 는 3D 기하 4종 포함 |
| `I-3` | 알림 전달 후 | 전달 기록 |
| `I-4` | 소견 생성 후 | 본문 · `notes[]` · `prompt_version` · `fallback` |

**공통 규약** — mTLS + `X-Signature`(HMAC-SHA256 over `ts + "." + body`) + `Idempotency-Key` 필수. 지수 백오프로 재시도하되 **4xx 는 재시도하지 않는다.**

**"저장소에 올라간 것은 반드시 DB 에 등록된다"** 가 규칙이다. 그래서 I-1 이 실패하면 업로드 자체를 되돌린다. 추론 서비스가 쓰기 키로 직접 올리면 이 경로 밖으로 나가 등록 안 된 파일이 생긴다.

### 설정값 — 틀리면 조용히 잘못 도는 것들

| 환경변수 | 기본 | 틀렸을 때 |
|---|---|---|
| `TICKET_KEY` · `CALLBACK_SECRET` | 없음(필수) | Django 와 **똑같아야** 한다. 다르면 티켓·콜백이 전부 막힌다 |
| `GARAGE_ENDPOINT` | `garage:3900` | Docker 안에서 호스트 터널을 부르려면 `host.docker.internal`. 컨테이너의 127.0.0.1 은 컨테이너 자신이다 |
| `GARAGE_BUCKET_DERIVED` | `empatho-derived` | **비면 파생물 경로가 404.** 조용히 원본 버킷에 쓰지 않는다 — 설정 누락과 정상 동작이 같아 보이면 아무도 모른 채 원본이 더러워진다 |
| `ORTHANC_URL` | 비어 있음 | 비면 I-2 만 보내고 전송은 건너뛴다(개발용) |
| `REPORT_BASE` · `REPORT_TIMEOUT` | `http://tunnel:8002` · `2m` | 짧게 잡으면 멀쩡한 요청이 끊긴다. 모델이 내려가 있으면 적재 3초 + 대기 |
| `CORS_ORIGINS` | 비어 있음 | 브라우저가 Go 를 직접 부른다. 안 적으면 업로드·SSE 가 사전 요청에서 막힌다 |
| `GW_LOCAL_ROOT` · `GW_DEV` | 비어 있음 | **운영 .env 에는 두 줄 다 없어야 한다.** 컨테이너 디스크에 쓰고 재시작하면 사라진다 |

## 사슬 — 한 장이 들어와서 소견이 나갈 때까지

```
브라우저 ──── Django /tickets 에서 HS256 JWT
    │         바이트가 Django 를 안 거치는 것이 설계 목적
    ▼
★ file-gateway :8091     티켓 검증 → Garage PUT → DICOM 파싱 → Orthanc STOW
    │                     맘모 DICOM 도 Orthanc 에 넣는다
    ▼
★ → Django               I-1 storage_object · I-2 dicom metadata
    ▼
  Celery → FastAPI       소켓 1~6 GPU 추론   ← Go 안 거침
    │                     맘모는 소켓 4b. sockets/mammo.py 가
★   │                     infer_mammo.load_model / predict 를 직접 부른다
    │                     워커 1개 · 락으로 직렬화 · 적재 17초
    │                     GPU 상주 6.7GB · 추론 중 최대 11.3GB
    ▼
★ llm-proxy :8090        → 리포트 서버 :8002
    ▼
★ → Django               I-4 report narrative
    ▼
★ notify :8092           SSE. 버퍼 넘치면 resync

★ = 내 담당
```

| # | 무엇이 어긋났나 | 누가 | 할 일 |

| 1 | 검출 JSON 에 좌표계 표시가 없다 | 내 쪽 | 최상위에 `"frame": "tissue_crop"` 과 영상별 `origin`. 이 값이 조직 상자 기준인 줄 모르면 조용히 어긋난다 |
| 2 | 리포트 서버가 `evidence` 를 못 받는다. Go 는 `{result, evidence}` 를 보내는데 본문 전체가 `result` 에 바인딩된다 | 리포트 서버 · **급함** | `report(socket_id, result, evidence=[])`. 지금 그대로면 **200 에 틀린 소견**이 나간다. 422 도 500 도 아니라 아무도 못 알아챈다 |

| 4 | 소켓 4b 가 `infer_mammo.abstain_result()` 를 안 쓴다 | FastAPI | 안 쓰면 기권 봉투가 또 두 벌이 된다. 봉투는 한 곳에서만 만들어야 한다 |
| 5 | `birads` 가 `int` 에서 `str` 로 바뀐다 (`"4a"` · `"4c"`) | 화면 · DB | **응답 계약 변경이다.** 숫자로 파싱하는 곳이 있으면 깨진다. 등급 비교는 `biopsy` 칸을 쓸 것 — `"4a" >= 4` 는 성립하지 않는다 |
| 6 | 미세석회 `size_px`·`size_mm` 가 **null** 이고 `display` 칸이 생겼다 | 화면 | 화면은 `display.box` 를 그린다. `claims_extent` 가 false 면 그 표시는 병변 크기가 아니다 |
| 7 | `thresholds.yaml` 참고 주석이 후처리 전 값(`0.594`·`0.767`)이다 | 임계값 담당 | **값은 안 고친다.** `mammo:` 를 `{}` 로 두어 `infer_mammo.DEFAULTS` 를 따르기로 정해졌다 — 같은 상수가 두 곳에 생기지 않는다. 주석만 고친다 |
| 8 | 맘모 판독 실측이 없다 (적재 17초는 실측, 판독은 명세값 5~20초) | 내 쪽 | 타일 방식이라 영상마다 크게 흔들린다. 평균이 아니라 **95백분위**로 내야 한다. 아래 타임아웃 결정이 여기 걸려 있다 |
| 9 | 소켓별 판독 타임아웃 숫자가 어디에도 없다 | Celery · FastAPI | 하나로 덮으면 MRI 에 맞춘 값이 다른 소켓 장애를 몇 분씩 붙든다 |
| 10 | `REPORT_TIMEOUT 2m` 이 종합 리포트에 충분한지 모른다 | 내 쪽 | 검사 소견 하나는 1초 미만이지만 종합은 입력이 길다. `prompts/summary.py` 가 나오면 잰다 |
| 11 | `laterality` 가 팀 명세는 필수인데 헤더에 없으면 null | **팀 결정** | 필수로 쓸 거면 받는 쪽에서 채우는 경로가 필요. 아니면 선택으로 내린다 |
| 12 | `descriptor_name` 이 초음파 7종으로만 정의됨. 맘모 `calctype`·`calcdist`·`finding` 이 없고 `shape`·`margin` 은 **이름은 같은데 값 집합이 다르다** | **팀 결정** | ① 검사 종류를 접두어로 ② `modality` 동반 ③ DB 철자에 맞춘다. **②는 권하지 않는다** — 화면이 `modality` 를 안 보는 경로가 하나만 생겨도 조용히 틀린다 |
| 13 | 게이트 규칙이 CORAL 경계 확률 넷을 전제하는데 **응답에 `gate_flags` 필드 자체가 없다.** 초음파도 셋만 낸다 | **팀 결정** | 규칙을 실제 나오는 값에 맞춰 다시 쓰거나, 맘모처럼 `limitations` 로 통일 |
| 14 | `area_pixel` 을 채울 수 없다 (분할 라벨 없음) | **팀 결정** | 맘모는 비운다. 화면이 이 값에 의존하면 안 된다 |
| 15 | 접속 안내서가 "Orthanc 은 MRI 전용" 이라고 적고 있다 | 문서 오류 | 맘모 DICOM 도 Orthanc 에 들어간다. 그대로 믿으면 `ORTHANC_URL` 을 비우고 띄운다 |

### 정리된 것

| 무엇이었나 | 어떻게 |
|---|---|
| ~~`topk` 와 임계값이 채점·서빙에서 다르다~~ | 채점기를 서빙에 맞추고 작동점을 **종류당 오탐 2개**로 정한 뒤 다시 쟀다. `topk` 는 `0`(제한 없음) — 병변 손실이 0이고 오탐 예산도 이미 다 쓴다 |

## 성능 (2026-09-04 · 작동점 종류당 오탐 2개)

후처리 두 가지(조직 타일 필터 30% · 깊이 가중)가 추론 경로에 들어가 있고,
작동점을 **종류당 오탐 2개/영상**으로 잡았다.
**코드에는 반영됐다. 서빙 인스턴스가 다시 떠야 실제로 적용된다.**

### 검출기 — FROC 중심 명중

| | 후처리 전 · 오탐 1개 | 후처리 후 · 오탐 1개 | **후처리 후 · 종류당 2개** |
|---|---|---|---|
| 미세석회 | 57.9% | 63.7% | **77.5%** |
| 종괴 | 56.4% | 66.0% | **76.7%** |

두 번의 개선은 성격이 다르다. 앞은 **같은 자리를 다르게 재서** 얻었고
(후처리가 순위를 고쳤다), 뒤는 **자리를 옮겨서** 얻었다(오탐을 더 받았다).

오탐을 무제한 허용할 때의 상한은 석회 94.9% · 종괴 95.3% 이고, 후처리
전후가 소수점 셋째 자리까지 같다. **병변은 이미 찾고 있고 순위에 막혀 있다.**

### 끝단 — 검출부터 조직검사 권고까지

| | 위치를 알려주면 | 스스로 찾으면 |
|---|---|---|
| 미세석회 | 98.1% | **77.3%** |
| 종괴 | 82.7% | **63.8%** |
| **합계** | **90.0%** | **70.2%** |

```
90.0%  ──검출 -18.3%p──▶  71.7%  ──상자 품질 -1.5%p──▶  70.2%
```

잃는 19.8%p 중 **92%가 검출 단계**다. 검출기 몫 79.7% · 서술어 몫 88.0%.
서술어는 위치를 알려주면 90.0% 를 한다. 병목은 검출이다.

### 작동점을 왜 종류당 2개로 잡았나

세 지점을 끝까지 다 재고 골랐다.

| 종류당 오탐 | 끝단 | 검출기 몫 | 헛검출/영상 | **조직검사 권고/영상** |
|---|---|---|---|---|
| 1개 | 60.3% | 69.3% | 1.97 | **1.34** |
| **2개** | **70.2%** | **79.7%** | 3.87 | **2.72** |
| 4개 | 76.3% | 86.1% | 7.87 | **5.64** |

1→2 는 검출기 +10.4%p 에 권고 +1.4개, 2→4 는 +6.4%p 에 권고 +2.9개다.
**두 번째 계단이 훨씬 비싸다.** 영상 한 장마다 조직검사 후보를 다섯 개씩
내밀면 아무도 안 본다.

⚠ **「오탐 2개」는 종류당이다.** 석회와 종괴를 따로 재므로 화면에 뜨는
헛표시는 합쳐서 3.87개다. 이 값을 한 자리로 줄여 말하면 안 된다.

### 미세석회는 상자가 아니라 표식으로 낸다

석회 검출 상자는 정답의 **절반 크기**다 — 가로 0.58 · 세로 0.53 ·
넓이 0.30 (중심이 맞은 검출만, 중앙값). 편차도 커서 넓이 25퍼 0.07 ·
75퍼 1.17 이라 일률적으로 키워도 안 된다. 1.5배로 키우니 IoU 상한이
86.5 → 78.1% 로 오히려 떨어졌다.

중심이 완벽해도 크기가 절반이면 IoU 는 0.25 라 0.3 문턱에 못 미친다.
석회의 중심 63.7% 대 IoU 42.1% 가 그 산수다.

상자는 「병변이 이만큼 크다」는 주장인데 그 주장을 할 근거가 없다. 크기를
말하지 않는 고정 표식(조직 상자 넓이의 0.5%)으로 바꿨다. **재현율은 한
자리도 안 잃는다** — 중심 명중은 표시 크기와 무관하다.

종괴는 상자를 유지한다. 가로 0.88 · IoU 64.5% 대 중심 66.0% 로 정확하다.

응답에 `display{shape, box, claims_extent}` 가 생겼고, 미세석회의
`ai_size_px`·`ai_size_mm` 는 **null** 이다. 절반으로, 그것도 들쭉날쭉 틀리게
말하느니 말하지 않는 것이 맞다.

### 외부 검증 (VinDr-Mammo 435장)

재학습도 임계값 재조정도 없이 CBIS 에서 나온 설정을 그대로 걸었다.

| 종류당 오탐 2개 | CBIS (학습 도메인) | VinDr (외부) | 차이 |
|---|---|---|---|
| 미세석회 | 77.5% | **60.3%** | −17.2 |
| 종괴 | 76.7% | **63.9%** | −12.8 |

오탐 1개 지점에서도 격차는 같은 크기였다(−15.4 / −15.6). **작동점을 옮겨도
도메인 격차 자체는 안 줄어든다.** 줄어들 이유도 없다.

**후처리는 외부에서도 통한다.** 같은 지점에서 깊이 가중을 끄면 석회 58.7% ·
종괴 63.0% 이고, CBIS 에서 정한 λ 를 손대지 않고 걸면 60.3% · 63.9% 가 된다.
이 데이터에만 맞춘 규칙이 아니라는 근거다.

**종괴는 상한이 VinDr 에서 오히려 높다** — 96.1% 대 CBIS 95.3%. 병변을 못
찾는 것이 아니라 순위가 무너진다. 도메인 격차의 성격이 「안 보인다」가 아니라
**「순서를 못 매긴다」**라는 뜻이다. 다른 장비 · 다른 기관 영상을 쓸 거면 그만큼 낮게 잡아야 한다.
원인은 종류마다 다르다 — 미세석회는 **해상도**(화소 간격이 굵으면
약해진다), 종괴는 해상도가 아니다.

후처리는 재조정 없이 CBIS 에서 나온 값을 그대로 걸었는데 외부에서도 올랐다.
깊이 가중의 λ 도 CBIS 에서 측정한 분리도로 정한 값을 손대지 않고 썼다.
