# 맘모 판독 보조 — 서빙 응답 명세

`serve_mammo.py` / `infer_mammo.predict()` 가 돌려주는 것의 전부.
기준 코드는 `infer_mammo.py` 의 `predict()` 반환문과 `_describe()`.
운영점은 2026-09-04 에폭 6 + 후처리 확정본
(wbf@0.3 + 조직 마스크 필터 + 조직 타일 30% + 깊이 가중).

받는 쪽이 이 문서에서 **먼저 읽어야 할 세 줄**

1. `lesions` 가 비어 있어도 「정상」이 아니다. `summary.abstained` 를 볼 것.
2. `lesion.kind` 는 신뢰하지 마라. 위치는 맞는데 종류가 틀리는 경우가 있다.
3. `limitations` 가 비어 있지 않다. 그 필드들은 우리가 못 채우는 것이고, 이유가 값으로 들어 있다.

## 1. 엔드포인트

| 메서드 | 경로 | 입력 | 출력 |
|---|---|---|---|
| POST | `/mammo/predict` | multipart `file` = DICOM 또는 PNG 1장 | 아래 §2 JSON |
| POST | `/mammo/overlay` | 같음 + `width`(기본 1400) | PNG. 요약은 `X-Mammo-Summary` 헤더 |
| GET | `/mammo/info` | — | 운영점 · 성능 · limitations |
| GET | `/mammo/limitations` | — | limitations 만 |
| GET | `/health` | — | `{ready, error, load_seconds, busy, auth}` |

`predict` 는 폼 필드로 요청 단위 덮어쓰기를 받는다 — `score_calc`, `score_mass`,
`tissue_frac`, `topk`. 안 주면 확정 운영점.

### 상태 코드

| 코드 | 뜻 | 받는 쪽 처리 |
|---|---|---|
| 200 | 정상. **기권도 200 이다** | `summary.abstained` 를 반드시 확인 |
| 401 | `X-API-Key` 불일치 | `MAMMO_API_KEY` 를 켠 경우만 |
| 400 | 빈 파일 · 못 읽는 영상 · 추론 실패 | 메시지에 예외 종류가 들어 있다 |
| 413 | 120MB 초과 | |
| 503 | 모델 적재 중(실측 17초) 또는 적재 실패 | 메시지에 경과 초 또는 실패 사유 |

503 은 재시도하면 된다. 서버가 죽은 게 아니라 아직 안 올라온 것이다.

## 4. `dicom`

`photometric`, `laterality`, `view`, `study_uid`, `sop_uid`.
전부 헤더에서 그대로 읽은 값이고, 태그가 없으면 개별 필드가 null 이다.

> ⚠ `laterality` 와 `view` 는 **우리가 만드는 값이 아니라 헤더를 옮기는 값**이다.
> 팀 명세에서 `laterality` 는 필수(Y)인데, 헤더에 없으면 null 이 나간다.
> 필수로 쓸 거면 받는 쪽에서 파일명·검사 정보로 채우는 경로가 따로 있어야 한다.

`photometric` 이 `MONOCHROME1` 이면 우리가 이미 뒤집어서 처리했다.
받는 쪽이 또 뒤집으면 안 된다. 그냥 기록용이다.

## 5. `lesions[]`

| 필드 | 타입 | 항상? | 내용 |
|---|---|---|---|
| `id` | int | Y | 1부터. **점수 내림차순** |
| `kind` | `"mass"` \| `"calcification"` | Y | 아래 경고 |
| `box` | `[x0,y0,x1,y1]` | Y | **원본 영상 화소 좌표**. 소수 1자리 |
| `score` | number | Y | 검출기 점수 0~1 |
| `crop` | `[x0,y0,x1,y1]` | Y | 서술어 모델에 실제로 넣은 영역(= box + 사방 20px, 영상 밖은 자름) |
| `descriptors` | object | Y | §5.2. **빈 객체 가능** |
| `birads` | str \| **null** | Y | 규칙표 결과. `"2"` `"3"` `"4a"` `"4b"` `"4c"` `"5"`. null = 규칙표가 등급을 못 냈다 |
| `biopsy` | bool | Y | 등급 4 이상. **`birads` 문자열로 직접 비교하지 말 것** — `"4a" >= 4` 는 성립하지 않는다. 이 칸을 쓸 것 |
| `certainty` | number | Y | Σ\|pᵢ−0.5\|. 축별 최대확률 기준 |
| `confidence` | `"high"` \| `"low"` | Y | 축 하나라도 `verify` 면 low |
| `ai_size_px` | number \| null | Y | 박스 긴 변. **AI 원본값 · 불변** |
| `ai_size_mm` | number \| null | Y | `ai_size_px × pixel_spacing_mm`. 간격 없으면 null |
| `ai_size_measurable` | bool | Y | `pixel_spacing_mm` 유무 |
| `certainty_axes` | int | Y | 서술어 축 수. 석회 2 · 종괴 3. §5.3 |
| `size_omitted_reason` | string \| **null** | Y | 크기를 안 낸 사유. null 이면 냈다. §5.1 |
| `display` | object | Y | 화면에 어떻게 그릴지. §5.1 |
| `frame` | string | Y | 항상 `"original_pixel"`. §5.1 |
| `evidence_id` | string \| null | Y | 판독문이 이 병변을 가리키는 이름표. `MG-RCC-01` 꼴 — 시야를 넣어 **검사 안에서 겹치지 않는다.** 문안 규칙은 `evidence_text.md` |
| `evidence_id_omitted_reason` | string \| null | Y | `evidence_id` 가 null 인 사유. 시야를 못 읽은 경우 등 |
| `aspect_ratio` | number \| null | Y | 세로/가로 |

> ⚠ **`kind` 를 신뢰하지 마라.** 종류는 분류 헤드가 아니라 **텍스트 질의**에서
> 나온다("mass" / "calcification" 각각 한 번씩 돌린다). 시연 3장 전부에서
> 미세석회 질의가 종괴에 반응했다 — **위치는 맞고 종류가 틀린다.** 종류가
> 틀리면 그 병변에 잘못된 서술어 모델이 붙고, 따라서 `descriptors` 와
> `birads` 도 함께 틀린다. 화면에는 종류를 단정하지 말고 같이 보여줄 것.

> ⚠ `box` 는 **박스이지 병변 경계가 아니다.** 맘모 학습 데이터에 분할 라벨이
> 없어서 마스크를 안 낸다. 팀 명세의 `area_pixel` 은 채우지 않는다 —
> 박스 면적을 병변 면적으로 넣으면 그대로 오독된다.

### 5.1 표시 방법 — `display` · `frame` · 크기

**`box` 를 그대로 네모로 그리면 안 된다.** `display.shape` 를 보고 그린다.

| `kind` | `display.shape` | `display.claims_extent` | 크기 |
|---|---|---|---|
| `calcification` | `"marker"` | `false` | `ai_size_px`·`ai_size_mm` 이 **null** |
| `mass` | `"box"` | `true` | 낸다 |

미세석회 상자는 **정답 병변의 절반 크기**로 나온다. 중심은 맞아서 검출
지표는 통과하지만, 네모로 그리면 **병변이 실제보다 작다고 주장하는 그림**이
된다. 그래서 표식으로 내고 크기를 안 낸다.

> ⚠ **`kind` 를 보고 판단하지 마라.** 종류는 틀릴 수 있다(아래 경고).
> 그리는 규칙은 `display.shape` 하나로 정해진다.

`display.box` 는 표식을 그릴 자리이고, `lesions[].box` 는 **일부러 안 바꾼다** —
서술어 모델이 그 상자에서 조각을 오려 등급을 내므로 바꾸면 등급이 같이 바뀐다.

#### `size_omitted_reason`

```
null                            크기를 냈다
"microcalc_extent_unreliable"   범위를 못 믿어서 안 냈다   → "크기 판단 보류"
"no_pixel_spacing"              화소 간격이 없어서 못 냈다 → "크기 미산출"
```

**두 사유는 화면 문구가 달라야 한다.** `ai_size_measurable` 한 칸으로 합치면
뒤에서 구분이 안 된다.

#### `frame`

`box` · `crop` · `display.box` 는 전부 **원본 영상 화소 기준**이다.
값에 `"original_pixel"` 로 적혀 나간다.

> ⚠ 내부 검출 파일(`archive/outputs/tile_dets_*.json`)의 상자는 **조직 상자
> 기준**이라 다르다. 그쪽에는 `"frame": "tissue_crop"` 과 영상별 `origin` 이
> 박혀 있고, 원본으로 되돌리려면 `origin` 의 앞 두 값을 더한다.
> **두 파일의 상자를 섞어 쓰면 영상마다 수백 화소씩 어긋나는데 오류는 안 난다.**

DB 스키마 v8 의 `lesion.detail.frame` 이 이 값을 그대로 받는다.

### 5.2 DB v10 과의 대응

응답의 이름을 **DB 컬럼에 맞췄다.** v10 은 라이브 DB 에서 뽑은 것이라
이름이 다르면 받는 쪽이 매핑을 짐작하게 되고, 짐작은 오류를 안 낸다 —
조용히 null 이 들어간다.

| 응답 | `lesion` 컬럼 | 비고 |
|---|---|---|
| `ai_size_px` | `ai_size_px` | **AI 원본값 · 불변** |
| `ai_size_mm` | `ai_size_mm` | 〃 |
| `ai_size_measurable` | `ai_size_measurable` | 〃 |
| — | `measured_size_mm` · `measured_size_px` | **판독의 캘리퍼 값. 우리가 안 건드린다** |
| `birads` | `birads_model` | |
| `certainty` | `certainty` | Σ\|pᵢ−0.5\| |
| 나머지 전부 | `detail` (JSONB) | `box` · `frame` · `score` · `display` · `size_omitted_reason` · `descriptors` · `certainty_axes` · `needs_biopsy` · `crop` · `evidence_id` · `evidence_id_omitted_reason` |

> ⚠ **`detail` 의 키 목록은 여기가 원본이다.** v10 은 DB 덤프라 JSONB 안을
> 적지 않는다. 이 표가 우리와 Django 사이의 계약이다.

`size_omitted_reason` 은 v10 에 컬럼이 없다. `detail` 키로 남으며
**DB 변경이 필요 없다** — `ai_size_measurable` 이 bool 하나라 두 사유가
구분되지 않기 때문에 필요하다(§5.1).

### 5.3 `certainty` 를 종류 사이에 비교하지 말 것

`certainty` 는 `Σ|pᵢ−0.5|` 인데 **축 개수가 종류마다 다르다.**

| 종류 | 축 | `certainty` 최대 |
|---|---|---|
| 미세석회 | `calctype` · `calcdist` | **1.0** |
| 종괴 | `shape` · `margin` · `finding` | **1.5** |

같은 자로 잰 값이 아니다. 병변을 **종류 섞어 정렬하거나 문턱을 걸면
미세석회가 구조적으로 덜 확실해 보인다.** 실제로 덜 확실한 것이 아니라
축이 하나 적어서다.

그래서 `certainty_axes` 를 같이 낸다.

```
비교 가능한 값 = certainty / certainty_axes
```

DB 컬럼 정의를 바꾸지 않고 받는 쪽에서 맞출 수 있다.

### 5.4 `descriptors`

`{축이름: {value, confidence, verify}}` 형태.

```json
"descriptors": {
  "calctype":  {"value": "PLEOMORPHIC", "confidence": 0.8123, "verify": false},
  "calcdist":  {"value": "CLUSTERED",   "confidence": 0.5540, "verify": true}
}
```

- `confidence` — 그 값의 확률(0~1)
- `verify` — `confidence < 0.60` 이면 true. 화면에 「직접 확인」을 붙일 것

**축은 종류마다 다르다.**

| `kind` | 축 | 값 |
|---|---|---|
| `mass` | `shape` | `OVAL` `IRREGULAR` `ROUND` |
| | `margin` | `CIRCUMSCRIBED` `INDISTINCT` `SPICULATED` `OBSCURED` `MICROLOBULATED` |
| | `finding` | `ARCHITECTURAL_DISTORTION` `LYMPH_NODE` `FOCAL_ASYMMETRIC_DENSITY` `ASYMMETRIC_BREAST_TISSUE` |
| `calcification` | `calctype` | `PLEOMORPHIC` `PUNCTATE` `LUCENT_CENTER` `AMORPHOUS` `ROUND_AND_REGULAR` `FINE_LINEAR_BRANCHING` `VASCULAR` `COARSE` `BENIGN_TYPICAL` |
| | `calcdist` | `CLUSTERED` `SEGMENTAL` `LINEAR` `REGIONAL_OR_DIFFUSE` |

`shape` · `margin` · `calctype` · `calcdist` 는 **항상** 들어간다(최고확률 값을 채택).
`finding` 만 확률 0.5 이상일 때만 들어간다 — 없는 게 정상이다.

값 목록은 ACR BI-RADS 5판에 맞춰 병합한 결과다(`LOBULATED`→`OVAL`,
`ILL_DEFINED`→`INDISTINCT`, 전형적 양성 석회 5종→`BENIGN_TYPICAL`,
`REGIONAL`·`DIFFUSELY_SCATTERED`→`REGIONAL_OR_DIFFUSE`).
원본 CBIS 라벨 그대로가 아니다.

> 팀 명세 5-6 은 `descriptor_name` 을 초음파 7종으로만 정의해 두었다
> (`shape` `margin` `echo_pattern` `posterior` `halo` `calcification` `skin`).
> 위 5개 중 `calctype` `calcdist` `finding` 이 그 목록에 없고, `shape` 와
> `margin` 은 **이름은 같은데 값 집합이 초음파와 다르다.** 저장할 때
> modality 로 구분하지 않으면 두 모달리티 값이 한 컬럼에서 섞인다.

## 6. `summary`

| 필드 | 타입 | 내용 |
|---|---|---|
| `n_lesions` | int | `lesions` 길이 |
| `max_birads` | str \| null | 최고 등급. 병변이 없거나 전부 null 이면 null. 비교는 `0 1 2 3 4a 4b 4c 5 6` 순서다 — 사전 순 비교는 이 집합에서만 우연히 맞는다 |
| `biopsy` | bool | 하나라도 `biopsy` 면 true |
| `abstained` | bool | `n_lesions == 0` |
| `abstain_reason` | string \| null | `"no_detection_above_threshold"` |

> ⚠ **`abstained: true` 는 「정상」이 아니라 「판정 못 함」이다.**
> 서술어 모델을 조직검사가 확정된 병변 ROI 로만 학습해서 **「소견 없음」 클래스가
> 없다.** 임계값을 넘는 검출이 없으면 판정 자체를 할 수 없다.
> 화면에 「이상 없음」으로 표시하면 안 된다. 실제로 놓치는 병변이 있고
> (끝단 민감도 70.2%), 놓친 것은 이 응답에 아무 흔적도 남기지 않는다.

## 7. `detection` — 개수가 왜 이렇게 나왔는지

```json
"detection": {
  "tiles": 5,
  "per_class": {
    "calcification": {"candidates": 679, "outside_tissue": 137, "thin_tile": 3,
                      "below_threshold": 100, "kept": 1, "threshold": 0.448},
    "mass":          {"candidates": 792, "outside_tissue": 97,  "thin_tile": 3,
                      "below_threshold": 101, "kept": 1, "threshold": 0.462}
  }
}
```

※ 개수는 어떤 영상 하나의 값이다. 영상마다 크게 다르다.

| 필드 | 타입 | 내용 |
|---|---|---|
| `tiles` | int | 훑은 타일 수 |
| `candidates` | int | 타일 단계 후보 박스(문턱 `thr` 통과) |
| `outside_tissue` | int | 박스 면적의 절반 이상이 조직이 아니라 버린 수 |
| `thin_tile` | int | 조직 비율이 낮은 타일에서 나온 것이라 버린 수 |
| `below_threshold` | int | 합친 뒤 점수 문턱에 못 미쳐 버린 수 |
| `kept` | int | 최종. `lesions` 중 이 종류의 개수와 같다 |
| `threshold` | number | 이번 요청에 쓴 점수 문턱 |

`candidates` → `outside_tissue` 제외 → 합치기(wbf) → `thin_tile` 제외 →
깊이 가중 → `below_threshold` 제외 → `kept`.

순서가 중요하다. **박스 단위 조직 필터가 합치기보다 먼저**다 — 나중에 걸면
각인 글자에 붙은 박스가 이미 가중평균 좌표를 오염시킨 뒤다.
**타일 필터와 깊이 가중은 합치기 뒤**다. 그 순서로 측정했고, 앞으로 옮기면
겹친 타일 때문에 결과가 달라져 아래 수치를 그대로 쓸 수 없다.

깊이 가중은 아무것도 버리지 않는다 — 유방 경계에 붙은 박스의 점수를 눌러
순위만 바꾼다. 그래서 **점수 척도가 내려가고 임계값도 같이 내려간다.**
후처리를 끄면 임계값도 되돌려야 한다.

임계값이 두 번 내려갔는데 **이유가 다르다.**

| | 석회 | 종괴 | 왜 |
|---|---|---|---|
| 후처리 전 · 오탐 1개 | 0.594 | 0.767 | — |
| 후처리 후 · 오탐 1개 | 0.504 | 0.519 | 깊이 가중이 점수 척도를 낮췄다 |
| **후처리 후 · 종류당 2개** | **0.448** | **0.462** | **작동점을 옮겼다** (§10) |

앞의 것은 같은 자리를 다른 자로 잰 것이고, 뒤의 것은 자리를 옮긴 것이다.

`kept` 가 0인데 `candidates` 가 수천이면 「아무것도 없다」가 아니라
「점수가 낮아 전부 잘렸다」는 뜻이다. 여기서 임계값을 낮춰 재요청할 수 있다.

## 8. `limitations` — 못 채우는 것과 그 이유

값이 이유 문자열이다. **비워서 보내지 않는 이유** — 비면 받는 쪽이
「확인했는데 문제 없음」으로 읽는다.

| 키 | 이유 |
|---|---|
| `category_model` | CORAL 등급 헤드가 없다. 경로 A(서술어→규칙표)만 구현했다 |
| `boundaries` | 등급 경계 확률(ge_2·ge_3·ge_4·eq_5)은 CORAL 헤드에서 나온다 |
| `path_agreement` | 경로가 하나뿐이라 교차검증이 성립하지 않는다 |
| `gate_flags` | 게이트 1(단조성)·5(3↔4 경계)는 CORAL 확률이 필요하다. 대신 서술어 확신도(certainty)를 제공한다 |
| `clock_position` | 유두 검출을 하지 않는다 |
| `distance_from_nipple_mm` | 유두 검출을 하지 않는다 |

### 게이트에 대해 짚을 것

팀 명세 5-3 의 게이트는 전부 CORAL 경계 확률 p₁~p₄ 기반이고, 명세는
「게이트 1건 이상 → `abstained=true`」로 되어 있다. 맘모는 게이트를 하나도
계산할 수 없으므로 **이 규칙대로면 맘모는 영원히 기권하지 않는다.**
그런데 실제로는 기권한다(검출 0건). 기권 판정이 `gate_flags` 로 옮겨간
v3 구조에서 맘모의 기권 사유가 들어갈 자리가 없다.

우리가 채울 수 있는 것:

- **게이트 4(`low_certainty`)는 맘모에서도 성립한다.** 명세의 정의가
  Σ\|pᵢ−0.5\| < τ_conf 이고 우리 `certainty` 가 정확히 같은 식이다.
  다만 pᵢ 가 CORAL 경계 확률이 아니라 **서술어 축별 확률**이라 τ 를 따로
  잡아야 한다. 같은 τ 를 쓰면 안 된다.
- 기권 사유로 쓸 값이 하나 더 필요하다 — 검출 0건을 뜻하는 것.
  우리는 `summary.abstain_reason = "no_detection_above_threshold"` 로 낸다.

이 두 가지는 팀 결정 사항이다. 서빙 쪽은 값을 다 갖고 있으니 명세가 정해지면
매핑만 하면 된다.

## 9. 운영상 지켜야 하는 것

- **워커 1개.** 추론 중 GPU 최고 **10.6GB** 를 쓴다(실측). 32GB 카드를 다른
  작업과 나눠 쓰는 조건에서는 두 번째 워커가 안 올라간다.
- **추론은 한 번에 하나.** 서버가 락으로 직렬화한다. 동시 요청은 줄을 선다 —
  실패하지 않고 기다린다.
- **적재 20.2초** (실측). 그 전 요청은 503. 헬스체크로 `ready` 를 보고 붙일 것.
  가중치가 디스크 캐시에 없는 첫 적재는 더 걸릴 수 있다.
- **GPU — 적재 직후 6.9GB · 추론 중 최고 10.6GB** (실측). 최고점에서 할당자
  캐시는 121MB 뿐이라 **줄일 수 없는 값**이다. 용량은 **11~13GB** 로 잡을 것.

### 소요 시간 — 실측 (2026-09-07 · CBIS 40장)

| | 카드 단독에 가까울 때 | 카드를 나눠 쓸 때 |
|---|---|---|
| 사진 1장 95퍼 | 12.2초 | **26.9초** |
| 검사 1건(4장) 95퍼 | 49초 | **108초** |

같은 40장을 두 번 쟀고, 그 사이 다른 작업의 GPU 사용이 13GB → 21GB 로
늘었다. **값이 두 배가 됐다.**

느려지는 원인이 둘이고 성질이 다르다.

```
병변 수      바탕 7.7초 + 병변당 0.88초   예측 가능 · 상한 있다
GPU 경합     최댓값이 튄다                 예측 불가 · 상한 없다
```

⚠ 병변이 많아 느린 사진은 **다시 넣어도 똑같이 느리다.** 재시도로 못 넘긴다.
타임아웃을 짧게 잡으면 **병변이 많은 사진만 골라서** 죽는다.

### 타임아웃 — 세 겹으로 나눈다

| 겹 | 값 | 근거 | 넘으면 |
|---|---|---|---|
| 사진 1장 | **54초** | 95퍼 26.9초 × 2 | 그 사진만 버리고 다음으로 |
| 작업 1건(4장) | **216초** | × 4 | 작업을 실패로 적고 큐에서 뺀다 |
| 클라이언트 | **두지 않는다** | 202 즉시 반환 | — |

### ⚠ 판독 요청을 동기로 받지 말 것

워커가 1개이므로 요청이 겹치면 줄을 선다. 기다리는 시간은 추론 시간이 아니라
**앞에 밀린 것 + 내 것**이다. 검사 3건이 동시에 오면 세 번째는 시작도 못 한
채 약 430초를 기다린다. HTTP 를 그만큼 붙들면 게이트웨이 기본 타임아웃
(보통 30~60초)에 **우리가 정한 값과 무관하게** 먼저 잘린다.

```
POST /mammo/read        → 202 + job_id      즉시 반환
GET  /mammo/read/{id}   → 진행 상태 또는 결과
```

DB 스키마 v9 의 `ai_result.run_status` 가 이미 `queued · running · done ·
failed` 다. 큐 깊이에 상한을 두고 넘치면 503 으로 거절할 것 — 무한정 쌓이면
뒤에 온 요청이 위 216초를 넘겨 전부 실패한다.

> 근거와 측정 방법은 `docs/serving_capacity.md`.
- 업로드 영상은 디스크에 안 쓴다. 메모리에서 바로 읽는다.
- 기본 바인딩 `127.0.0.1`. 외부에 열려면 `MAMMO_API_KEY` 를 설정할 것.

## 10. 성능 (CBIS-DDSM test 598장 · 조직검사 대상 병변 459개)

운영 작동점은 **종류당 오탐 2개/영상**이다 (2026-09-04 결정 · 근거는 아래).

| | 규칙표 상한 | 서술어 모델 | + 검출까지 |
|---|---|---|---|
| 미세석회 | 100.0% | 98.2% | **77.3%** |
| 종괴 | 85.2% | 82.8% | **63.8%** |
| **합계** | **92.2%** | **90.0%** | **70.2%** |

FROC 종류당 오탐 2개/영상 · 중심 명중 — 석회 **77.5%** · 종괴 **76.7%**.
IoU>0.3 기준 — 석회 54.3% · 종괴 74.7%.

오탐을 무제한 허용할 때의 상한은 석회 94.9% · 종괴 95.3% 이고,
후처리 전후로 **소수점 셋째 자리까지 같다** — 찾던 병변을 하나도 잃지 않고
순위만 바꿨다는 뜻이다. **병변은 이미 찾고 있고 순위에 막혀 있다.**

### 작동점을 왜 종류당 2개로 잡았나

세 지점을 끝까지 재고 골랐다.

| 종류당 오탐 | 끝단 | 검출기 몫 | 영상당 헛검출 | **영상당 조직검사 권고** |
|---|---|---|---|---|
| 1개 | 60.3% | 69.3% | 1.97 | **1.34** |
| **2개** | **70.2%** | **79.7%** | 3.87 | **2.72** |
| 4개 | 76.3% | 86.1% | 7.87 | **5.64** |

1→2 는 검출기 +10.4%p 에 권고 +1.4개, 2→4 는 +6.4%p 에 권고 +2.9개다.
**두 번째 계단이 훨씬 비싸다.** 권고 5.64개는 판독 화면에서 쓸 수 없다 —
영상 한 장마다 조직검사 후보를 다섯 개씩 내밀면 아무도 안 본다.

⚠ **「오탐 2개」는 종류당이다.** 석회와 종괴를 따로 재므로 화면에 뜨는
헛표시는 합쳐서 3.87개다. 이 숫자를 한 자리로 줄여 말하면 안 된다.

mAP50 은 후처리 전 값(종괴 0.177 · 석회 0.037)이다. 새 설정에서는 다시 재지
않았다.

**「위치를 알려주면 90.0%, 스스로 찾으면 70.2%」** 가 이 시스템의 요약이다.

```
90.0%  ──검출 단계 -18.3%p──▶  71.7%  ──박스 품질 -1.5%p──▶  70.2%
```

잃는 19.8%p 중 **92%가 검출 단계**다. 서술어가 아니라 검출이 병목이라는
진단은 그대로고, 크기만 줄었다.
검출기 몫 366/459 = 79.7% · 서술어 몫 322/366 = 88.0%.

### 정상 유방에서는 무슨 말을 하나 (VinDr BI-RADS 1 · 300장 · 2026-09-08)

**위 표는 전부 병변이 있는 영상에서 나온 값이다.** CBIS 에는 정상 영상이 한
장도 없다(598장 중 0장). 그래서 따로 쟀다 — VinDr 에서 네 유방이 전부
BI-RADS 1 인 검사 75건(사진 300장)을 골랐다.

| | 사진 300장 |
|---|---|
| 검출이 하나도 없음 | **5.3%** |
| 뭔가 나옴 | 94.7% |
| 조직검사 권고까지 감 | **81.0%** |

| | 검사 75건 (사진 4장씩) |
|---|---|
| 네 장 다 조용함 | **0%** |
| 하나라도 울림 (재소환) | **100%** |

영상당 표시 **2.30개** (종괴 1.70 · 석회 0.60).

⚠ 이 값은 위 작동점의 **예산 안**이다. 「종류당 오탐 2개」는 영상당 4개까지
허용한 값이고 실측이 2.30 이다. **모델이 유난히 시끄러운 것이 아니라, 그
작동점이 검진용이 아니다.**

#### 문턱을 올려도 해결되지 않는다

양쪽 다 VinDr 로 재서 자료가 섞이는 문제를 없앴다.

| 문턱 | 석회 찾음 | 종괴 찾음 | 정상인데 부름 | 정상인데 조직검사 |
|---|---|---|---|---|
| **0.45 (지금)** | 43건 | 59건 | **100명** | 100명 |
| 0.55 | 26건 | 41건 | 91명 | 84명 |
| 0.60 | 16건 | 32건 | 53명 | 43명 |
| **0.70** | 2건 | 6건 | **11명** | 4명 |
| 0.75 | 0건 | 1건 | 0명 | 0명 |

*병변 100건 · 정상 여성 100명 기준 · 검출 단계 · 중심 명중*

정상 재소환이 검진 수준(11명)까지 내려가는 문턱에서 병변은 100건 중 2~6건
밖에 못 찾는다. **정상 유방의 오탐과 진짜 병변의 점수 분포가 거의 겹치므로,
선을 어디에 그어도 쓸 수 있는 지점이 없다.**

#### 받는 쪽이 반드시 알아야 할 것

```
아니다    검진 선별기 — 정상 여성을 걸러 내는 물건
맞다      판독 보조기 — 판독의가 이미 보는 영상에 표시를 얹는 물건
          **표시가 여러 개 뜨는 것을 전제로** 쓴다
```

화면에서 「표시가 떴다 = 뭔가 있다」로 읽히면 안 된다. 정상 유방에도 영상당
두세 개가 뜬다. `disclaimer` 필드가 이 사실을 문장으로 담고 있다(§2).

> 근거와 측정 방법은 `docs/screening_limit.md`.

### 외부 검증 (VinDr-Mammo 435장 · 2026-08-31)

재학습도 임계값 재조정도 없이 그대로 걸었다.

| 종류당 오탐 2개 | CBIS (학습 도메인) | VinDr (외부) | 차이 |
|---|---|---|---|
| 미세석회 | 77.5% | **60.3%** | −17.2 |
| 종괴 | 76.7% | **63.9%** | −12.8 |

참고로 오탐 1개 지점에서는 석회 63.7 → 48.3% · 종괴 66.0 → 50.4% 였다.
**작동점을 옮겨도 도메인 격차 자체는 안 줄어든다.**

후처리는 재조정 없이 걸었는데 외부에서도 올랐다 — 같은 지점에서 깊이 가중을
끄면 석회 58.7% · 종괴 63.0%, CBIS 에서 정한 λ 를 그대로 걸면 60.3% · 63.9%.

**종괴 상한은 VinDr 에서 오히려 높다**(96.1% 대 CBIS 95.3%). 병변을 못 찾는
것이 아니라 순위가 무너진다.

후처리는 **재조정 없이 CBIS 에서 나온 값을 그대로** 걸었다. 외부에서도
올랐다 — 석회 43.2→48.3% · 종괴 41.7→50.4%. 깊이 가중의 λ 도 CBIS 에서
측정한 분리도로 정한 값을 손대지 않고 썼다.

**받는 쪽이 알아야 할 것** — 위 §10 표의 70.2% 는 CBIS 기준이다. 다른 장비 ·
다른 기관 영상에서는 검출 민감도가 15%p 가량 낮다. 끝단 수치도 그만큼 낮게
잡아야 한다(VinDr 에는 서술어 라벨이 없어 끝단은 직접 못 쟀다).

두 데이터셋의 「정답」이 같은 것을 뜻하지 않는다 — CBIS 는 조직검사로 확정된
병변, VinDr 은 판독의가 표시한 소견이다.

**원인은 종류마다 다르다** (VinDr 을 1.42배로 키워 재확인).

| | 원인 | 확대 시 | 확대 + 후처리 |
|---|---|---|---|
| 미세석회 | **해상도** | 43.2 → 54.6% | **55.4%** |
| 종괴 | 해상도 아님 | 41.7 → 37.4% | 47.0% |

종괴는 확대하면 나빠지는데 **상한(max)은 96.1 → 99.1% 로 오른다.**
확대가 병변을 더 찾게 만들었는데 순위가 엉킨 것이라, 해상도가 무용한 것이
아니라 그 이득이 순위에 막혀 있다는 뜻이다.

즉 **화소 간격이 굵은 장비에서는 미세석회 검출이 특히 약해진다.**
받는 쪽이 장비별 성능 차이를 예상해야 한다면 이 축이 가장 크다.
(관찰 결과이며 운영점은 원본 크기 그대로다 — 종류별 배율을 채택하면
시험 데이터에 맞춘 것이 된다.)
