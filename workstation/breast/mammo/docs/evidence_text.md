# 맘모 병변 → `Evidence` 문안 규칙

2026-09-07 · 소켓 4b ↔ llm-proxy G-L1

llm-proxy 가 판독문을 쓸 때 받는 근거의 모양은 이것이다
(`gosvc/cmd/llm-proxy/main.go:62`).

```go
type Evidence struct {
    ID   string  // 문장이 [[e:ID]] 로 가리킨다
    Kind string  // lesion · measurement · pathology
    Text string  // 모델에게 보여줄 사실 한 줄
}
```

`Text` 한 줄이 **생성 모델이 그 병변에 대해 보는 전부**다. 여기 적힌 것만
판독문에 실릴 수 있고, 여기 적은 것은 대부분 실린다.

---

## 1. `ID` — 검사 안에서 유일해야 한다

### 지금 형식은 충돌한다

`evidence_id` 는 `ai_result` 하나 안에서 매겨진다.
맘모는 **검사 1건 = 사진 4장 = `ai_result` 4행**이다.
LCC · LMLO · RCC · RMLO 가 각자 자기 1번 병변에 `MG-01` 을 붙인다.

판독문은 검사 단위로 쓴다. 그러면 `[[e:MG-01]]` 이 어느 쪽 어느 시야인지
알 수 없다.

**llm-proxy 의 검사는 통과한다.** 목록에 `MG-01` 이 있기 때문이다.
통과하면서 틀리는 것이라 더 나쁘다 — 아무도 안 잡는다.

### 형식

```
MG-<시야>-<번호>       MG-RCC-01 · MG-LMLO-02
```

시야는 `LCC · LMLO · RCC · RMLO` 넷뿐이고 DICOM 태그에서 나온다.
번호는 `lesion_index`(점수 내림차순 1부터) 를 그대로 쓴다.

`Kind` 는 전부 `"lesion"` 이다.

---

## 2. `Text` — 사실만 나열하고, 문장은 모델이 만들게 둔다

우리가 매끄러운 문장을 쓰면 모델이 그 문장을 베낀다. 그러면 우리 표현의
군더더기가 판독문에 그대로 남고, 반대로 우리가 넣은 유보 표현이 다듬어지면서
사라지기도 한다. **사실을 나열해 주고 문장 만드는 일은 모델에게 맡긴다.**

### 미세석회

```
MG-RCC-01 · 우측 CC · 미세석회 의심 · 형태 무정형(0.90) ·
분포 군집(0.99) · 모델 BI-RADS 4c · 조직검사 권고 ·
크기 미산출(미세석회는 범위를 신뢰할 수 없어 내지 않음)
```

### 종괴

```
MG-LMLO-02 · 좌측 MLO · 종괴 의심 · 형태 불규칙(0.72) ·
경계 침상(0.81) · 소견 종괴(0.88) · 모델 BI-RADS 4b ·
조직검사 권고 · 장축 12.4mm(화소간격 0.083mm 기준)
```

축이 다른 이유 — 미세석회는 `calctype · calcdist` 둘, 종괴는
`shape · margin · finding` 셋이다.

### 크기가 없을 때

`ai_size_measurable` 이 `false` 면 **값 자리를 비우지 말고 사유를 적는다.**
비워 두면 모델이 다른 데서 숫자를 끌어온다.

```
size_omitted_reason = "microcalc_extent_unreliable"
  → "크기 미산출(미세석회는 범위를 신뢰할 수 없어 내지 않음)"

size_omitted_reason = "no_pixel_spacing"
  → "크기 미산출(영상에 화소 간격 정보가 없음)"
```

---

## 3. 넣으면 안 되는 것

### ① 미세석회의 크기

검출 상자가 **정답 병변의 절반 크기**로 나온다. 중심은 맞아서 검출 지표는
통과하지만 범위는 못 믿는다. 그래서 화면에서는 표식으로 내고 크기를 뺐다
(`display.shape = "marker"`).

`ai_size_px` 를 문장에 넣으면 **화면에서 막아 둔 것을 판독문이 뚫는다.**
판독문은 화면보다 오래 남고 법적 기록이 된다.

### ② 종류 단정

`kind` 는 틀릴 수 있다. 예시 영상 검토에서 **종괴 정답 위에 미세석회 표식이
찍힌 사례**를 확인했다. 종류 혼동은 실측된 문제다.

```
"미세석회가 있다"      ✗
"미세석회 의심"        ○
```

⚠ 모델이 「의심」을 떼고 단정형으로 다듬을 수 있다.
`extra_instruction` 에 **확신 수준을 올리지 말 것**을 명시한다(5절).

### ③ BI-RADS 를 판정처럼 쓰기

`birads_model` 은 **모델이 낸 값**이지 판독의의 판정이 아니다.
판정은 `assessment` 테이블에 따로 있고, 1차와 최종이 각각 행으로 남는다.

문안에 항상 **「모델 BI-RADS」**로 적는다. 「BI-RADS 4c」로만 적으면
판독문에서 확정 판정으로 읽힌다.

### ④ 검출 점수를 확률처럼 쓰기

`score` 는 검출기 점수이지 악성 확률이 아니다. 문안에 넣지 않는다.
서술어 신뢰도(`descriptors[].confidence`)는 **그 서술어에 대한 값**이므로
괄호 안에 축과 함께 적는다 — 병변 전체의 확신도로 읽히면 안 된다.

`malignancy_p` 는 v9 에서 **화면 비노출**이다. 문안에도 넣지 않는다.

### ⑤ 부재 주장

`DISCLAIMER` 에 이렇게 적혀 있다.

> 놓친 병변은 이 결과에 나타나지 않는다 (끝단 민감도 66.7%).

그러므로 「그 외 이상 소견 없음」 · 「양측 정상」 같은 문장은 **우리가 보증할
수 없다.** 근거로 낼 것이 없다.

> llm-proxy 설계가 이미 이것을 막는다. 부재를 주장하는 문장은 인용할 근거가
> 없어서 자동으로 버려진다. 다만 **의도한 방어는 아니므로** 문안 규칙에도
> 남겨 둔다.

### ⑥ 환자 식별 정보

이름 · 등록번호 · 생년월일. `Text` 는 외부 모델(Ollama)에 들어간다.

## 4. 병변이 하나도 없는 검사

`evidence` 가 비면 llm-proxy 가 **400 으로 거부한다**
(`main.go:137`). GPU 시간을 아끼려는 것이고 근거는 맞다.

그런데 병변이 없는 검사도 판독문은 나와야 한다. 지금 구조로는 못 쓴다.

### 두 가지 중 하나로 정해야 한다

**(가) 검사 자체를 근거로 넣는다**

```
ID   MG-RCC-00
Kind measurement
Text 우측 CC · 임계값을 넘는 검출 없음 · 검출기 끝단 민감도 66.7%
```

「없음」이 사실로서 근거가 된다. 다만 ⑤와 부딪히므로 **문안이 「검출되지
않았다」이지 「정상이다」가 아니어야 한다.**

**(나) 병변 0개면 llm-proxy 를 아예 안 부른다**

정형 문구를 Django 가 넣고, 판독의가 고친다. 생성 모델을 안 쓴다.

**(나)를 권한다.** 병변이 없는 검사에서 생성 모델이 할 수 있는 일이 없고,
할 게 없을 때 모델은 없는 말을 지어낸다.

### ⚠ 여기 확인 안 된 구멍이 있다

**CBIS-DDSM 에는 병변 없는 영상이 없다.** 예시 그림을 뽑을 때 확인했다
(598장 중 fp 버킷 0장).

즉 **정상 유방에 이 시스템이 무슨 말을 하는지 한 번도 안 봤다.**
(가)든 (나)든 그 전에 정상 영상 몇 장을 통과시켜 봐야 한다.
VinDr 에는 정상이 있다.

---

## 5. `extra_instruction` 에 넣을 것

`narrativeReq.Extra` 로 요청마다 붙는다.

```
- 근거에 적힌 확신 수준을 올리지 말 것.
  "의심" 을 "있음" 으로 바꾸지 말 것.
- 근거에 없는 크기 · 개수 · 위치를 쓰지 말 것.
- BI-RADS 는 반드시 "모델 BI-RADS" 로 적을 것.
- 이상이 없다는 취지의 문장을 쓰지 말 것.
```

세 번째와 네 번째는 문장 필터가 못 잡는다. 근거를 인용하면서 확신 수준만
바꾼 문장은 **근거 검사를 통과하기 때문이다.**

---

## 6. 돌아오는 값을 버리지 말 것

G-L1 응답의 `evidence_links` 는 **실제로 인용된 근거 id** 다
(`narrative.go:35` — 중복 없이, 나온 순서).

우리가 병변 3개를 넘겼는데 2개만 돌아오면, **판독문이 언급하지 않은 병변이
하나 있다**는 뜻이다.

그건 화면에 띄워야 한다. AI 가 찾은 병변인데 판독문에 안 들어갔다면
판독의가 뺀 것이든 생성 모델이 흘린 것이든 **사람이 알아야 한다.**

```
넘긴 근거 − evidence_links = 판독문에 안 실린 병변
```

한 줄이면 구할 수 있다. 지금은 이 값이 `report.evidence_links` 에 저장만
되고 아무도 안 볼 가능성이 크다.
